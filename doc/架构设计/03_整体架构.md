## 3. 整体架构

```
┌─────────────────────────────────────────────────────┐
│  UI 层 (egui)                                       │
│  左侧：文件列表（视频/图片标签页）+ 搜索            │
│  右侧：媒体区 —— 视频 mpv render API / 图片 egui 纹理 │
│         （图片含动图走纹理直显 13.4，mpv 只管视频； │
│           视频 PaintCallback 内 blit 到 egui 画布）  │
│  顶栏：打开/缓存管理；状态行：文件名/进度           │
└──────────────────┬──────────────────────────────────┘
                   │ 命令/事件
┌──────────────────▼──────────────────────────────────┐
│  应用核心 (状态机：浏览/打开中/播放/解压中)        │
└────┬───────────────────┬────────────────────────────┘
     │                   │
┌────▼───────────┐  ┌────▼──────────────────────┐  ┌────▼────────────────┐
│  播放服务       │  │  VarTidy 整理器（CLI）     │  │  encode 引擎（15）  │
│  mpv_ffi       │  │  分类 + 去重 + 批量抽取    │  │  dump 序列→视频     │
│  stream_cb     │  │  → 直写 var 仓库（只增）   │  │  headless mpv       │
└────┬───────────┘  └────┬──────────────────────┘  └────┬────────────────┘
     │                   │ open_entry / extract_batch    │ open_entry
     │                   │ （播放侧解压走 extract_session，见 11.4）
     │ Read + Seek       │                              │ Read + Seek
┌────▼───────────────────▼──────────────────────────────▼┐
│  VFS 层（核心抽象，播放/整理/编码共用）              │
│  trait ArchiveVFS { list(); open_entry() }           │
│  trait VirtualFile: Read + Seek { size() }           │
│  ├─ ZipVFS    （随机访问）                           │
│  ├─ SevenzVFS （BlockDecoder folder 直达；folder 结构│
│  │             探测 solid/非 solid 路由）            │
│  ├─ RarVFS    （探测固态；分卷合并处理）             │
│  └─ DirVFS    （目录媒体集合，见 4.2；FastSeek 直通）│
└────┬─────────────────────────────────────────────────┘
     │ 固态回退：后台解压
┌────▼──────────────────┐   ┌──────────────────────────┐
│  缓存管理器            │   │  配置服务                │
│  · 解压文件缓存（慢路径）│   │  config.toml 单文件：   │
│  · 解码块 LRU（快路径） │   │  缓存/扩展名/播放器参数/ │
│  · LRU 淘汰 + 上限控制  │   │  看图参数/VarTidy       │
└───────────────────────┘   └──────────────────────────┘
```

**架构不变量**：播放器、VarTidy 整理器、encode 编码引擎（15）是 VFS 层的三个并列
消费者，互不感知。未来扩展（音频播放、文本预览等）只需新增消费者，VFS 不动 ——
这是本设计的核心扩展点（encode 引擎即按此扩展点并入：单向依赖 vfs / player，
零反向依赖；壳（CLI/SendTo/UI）已全部接入，见 15.4/15.5）。

**双视角读法：控制平面 × 数据平面**。上图与下表是**控制平面**（模块静态依赖，
L1~L4，谁调用谁）；同一条链路换**数据平面**视角读，则是四条并行管道——
每条媒体通道拓扑不同，管道段边界即线程模型的线程边界：

```
数据平面（VFS → 解码 → 显示）：
  视频快路径 Stream（zip）: VirtualFile ──stream_cb 回调──→ mpv 内部线程拉流
                            → demux/decode → render API → UI 线程 blit → 屏幕
                            （mpv 主动拉，数据不流经任何业务代码）
  视频慢路径 Solid（solid 7z/RAR）: 解压会话线程 → cache 落地 → mpv 读本地
                            文件 → 同上
  非 solid 包 SingleFile:   同一解压会话机制，批 = 点击项本身、不组窗不预取
                            （复用进度/密码/取消机制，非"特殊 solid"）
  图片管道: open_entry → imgview 解码线程 → mpsc → UI 线程纹理 → egui 绘制
  raw 对比管道（§16）: open_entry → rawdec 软解线程 → mpsc → UI 线程纹理 → egui 绘制
  预取支线（不进屏幕）: VFS → 解压会话 → cache 落地（为上述管道备秒开）
```

两平面的关系：控制平面只做**声明式控制**（打开哪个源、会话目标指向谁、
缩放参数），数据从不流经编排层；帧级调度自治在 L2 能力服务内部线程；
"显示"拆两半——显示物的生产（纹理/解码帧）在 L2 后台线程，最终上屏绘制
在 UI 线程交互壳（egui 绘制独占）。管道状态事件（FileDone、mpv 属性、
解码完成）反向回流控制平面，驱动进度条/覆盖层/徽标。

**排查分工**：画面错位/发黑/颜色不对 → 查数据平面（§8，配
[DEVLOG §8](../架构落地开发/08_RAW媒体支持专项.md)）；点击无响应/状态不
更新/播放劫持 → 查控制平面（配 [DEVLOG §4](../架构落地开发/04_点击状态机排查手册.md)）。

**线程模型**（全进程 5 类线程，边界即数据流边界）：

| 线程 | 职责 | 与 UI 线程的通信 |
|---|---|---|
| UI 线程 | egui 渲染、快捷键、mpv 命令下发、全部状态机 | —（mpv handle 线程安全，但仅 UI 线程持有） |
| 打开线程（OpenJob） | 每包一条：解析压缩包头 + 列目录 + 密码探测 | mpsc channel 交 UI 应用；带代际号（gen），快速连续切换时旧结果丢弃 |
| mpv 事件泵线程 | 常驻：`wait_event(0.2)` 消费 mpv 事件（EOF / 文件切换 / 属性订阅推送）写入原子缓存 | 原子变量——UI 帧内零锁读（见 13.2 订阅缓存） |
| mpv 内部线程 | demux / decode / playloop，经 stream_cb 回调读压缩包数据 | 仅通过 REGISTRY（`Arc<dyn VirtualFile>`）共享 |
| 解压会话线程 | 每包一条持久解码会话（targets / focus 经 `Arc<Mutex<SessionState>>` 共享）；跳转 = 重定向目标、永不重启解码 | mpsc 报告进度 / 结果 / FileDone，UI 每帧轮询（见 11.4） |

**层级 × 模块映射**（依赖方向严格向下：L4 → L3 → L2 → L1。**目录 ≠ 层级**——
`ui/` 是 GUI 应用线整体，impl 块按功能切片，编排与交互同居一目录；能力服务
与基建在 crate 根，按能力命名）：

| 层 | 模块 | 说明 |
|---|---|---|
| L4 交互壳 | `ui/panels` · `ui/nav` · `ui/dialogs` · `ui/config_editor` | egui 绘制、按键分派、弹窗；不含业务决策 |
| L3 应用编排 | `ui/open` · `ui/extract` · `ui/compare`（平行线：`encode/mod.rs`） | 业务状态机——何时播 / 何时解压 / 会话编排；`extract` = 播放↔解压环形流（解压落地触发播放、播放目标决定解压批次），不可按功能名拆分 |
| L2 媒体能力服务 | `player/` · `imgview.rs` · `rawdec.rs` · `cache.rs` | 单一媒体通道能力封装（mpv / 图片纹理 / raw 软解 / 缓存），无业务决策 |
| L1 基建 | `vfs/` · `search/` · `config.rs` | VFS + 解压会话线程、搜索语法引擎（纯库非交互）、配置 |
| 平行应用线 | `vartidy/` · `encode/` | 各自编排、不进 GUI App；encode 消费 vfs + player（headless），vartidy 直消费 vfs |

| 模块 | 层 | 职责 |
