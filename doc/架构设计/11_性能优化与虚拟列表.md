## 11. 性能优化与虚拟列表设计（大包实战：27G ZIP / 56G 7z / 万级条目）

> 本章只保留大包性能专项的**机制设计**（批量解压摊薄、上下游预取、会话化、虚拟化三层）。
> 修复叙事（folder 直达 10 分钟卡顿、ZIP 头偏移写错）与虚拟列表四坑、多帧测试方法论
> 见 **[DEVLOG §1](../架构落地开发/01_大包性能专项.md)**。核心教训：**万级条目 + GB 级包，任何 O(N) 的每帧操作、任何"顺带"
> 的全量顺序解压，都会被放大成分钟级卡顿。**

### 11.1 解压链路优化

#### 7z folder 直达（最重要的一次修复）

- sevenz-rust 的 `SevenZReader::for_each_entries` 从 folder 0 顺序解压全部前置 folder
  （不利用 pack 流偏移）；改用 `BlockDecoder::new(folder_index, ...)` 直接 seek 到目标
  folder 的 pack 流偏移，**前置 folder 只 seek 不解压**——56G 固态包第 417 条目从
  10+ 分钟降到秒级。修复叙事与教训见 **[DEVLOG §1.1](../架构落地开发/01_大包性能专项.md)**。
- 该机制是固态包一切路径（播放定位 / 会话化 / VarTidy 原地整理）的性能前提。

#### 批量解压摊薄固态包定位成本（extract_batch + prefetch）

- 固态 folder 内部不可 seek，定位目标必须顺序解压一段前置数据——这部分成本无法消除，
  但可以**摊薄**：一次顺序解压流顺带解出一批条目（目标 + 顺序后续，总量 ≤ `extract.prefetch_downstream_mb`，
  默认 512MB）。翻页时直接命中缓存，无需再等。
- trait 层新增 `extract_batch(targets, cancel, progress, file_done)`：ZIP 用默认实现逐条循环；
  7z/RAR 各自实现单遍多目标（RAR 单次 processing 遍历内 skip 非目标、extract 目标）。
- 取消机制：`Arc<AtomicBool>`。批外跳转的"取消重起"后被解压会话化取代（见 11.4），
  cancel 只剩一个用途：切换压缩包时终止解码线程（取消点打日志的坑见 [DEVLOG §1.3](../架构落地开发/01_大包性能专项.md)）。

#### 上游预取（免费区）：随机跳看后往回翻也能命中

- 定位目标时，前置数据**必然被顺序解掉丢弃**（7z 是目标 folder 内从头解码到目标、
  solid RAR 是逐条 skip 消费前缀）——把这段"本来要丢的字节"改写入缓存，解码零增量，
  只增加磁盘写入。随机跳看场景下用户往回翻直接命中缓存，无需再付定位成本。
- 免费区边界由格式决定（trait `locate_start`，默认 None = 不适用）：solid 7z = 目标所在
  folder 首条目（跨 folder 只 seek 不解压，上游预取**不得超出 folder 边界**——配置
  512MB 但 folder 前缀不足时实取以边界为准）；solid RAR = 整个前缀（unrar 无 folder
  直达）；**非 solid RAR 与全独立 folder 的非 solid 7z 无免费区**（二者定位都是廉价
  跳转，上游预取等于白白解码，见下）。
- **本质 = 伴随量，不是配额**：上游预取是定位解码流推进过程中的**顺手落盘**——流
  本来就要流过整个免费区，落盘只是把流经字节留下，解码零增量。配置键
  `extract.prefetch_upstream_max_mb`（默认 512MB，0 = 关闭）是**最大上限而非目标
  量**——与下游 `prefetch_downstream_mb`（尽量取满）语义不对称，故键名带 max：
  实取多少取决于免费区（folder 前缀）大小与已缓存分布，通常小于该值，
  **只封顶不凑满**：folder 前缀不足时实取以边界为准，绝不回头补解凑满（那是
  本末倒置）。
  与下游预取 `prefetch_downstream_mb` 互不挤占；**按包内物理序全量收集，不做
  view 可见过滤**——夹缝条目（搜索过滤/标签页隐藏/非媒体文件）解码本来就要穿过，
  可见过滤只省磁盘，磁盘成本由 LRU 上限兜底、预取 size 用户自控（见 11.7 铁律一）。
  上下游两批天然不重叠（下游从 `entry_idx+1` 起、上游止于 `entry_idx`），无需去重。
- **写入窗口紧贴锚点（R1）**：流过 ≠ 全落——预算决定免费区里**哪一段**写盘。从
  `entry_idx-1` 向前收，落盘段 = `[锚点-预算, 锚点)` 而非从 folder 起点顺收——
  folder 开头离锚点最远，顺序浏览时最先被复用、预取价值最低；解码流照样从 folder
  起点顺流（物理序不变），只是起点段流过不落盘，进度条顺序因此为
  skip 前缀 → 上游落盘 → 锚点，与设计意图一致。**预算字节含已缓存项 size**（下游同规则）：
  缓存区不再"免费穿过"——窗口 = `[锚点-预算, 锚点+预算]` 随锚点整体滑动，且被上一批已解
  区域的缓存字节顶住，永不越过批起点收编解码头身后的漏网项（顺带落盘的前提是解码流
  "将来还会流过"，身后的项收编了也够不着；实测 8 项漏网曾触发 114 秒 folder 前缀重解，见 DEVLOG §1.9）。
- 进度显示配合：前置文件先于目标落地，写文件阶段字节按目标尺寸封顶
  （否则进度条出现"300MB / 60MB"怪相）；完成提示改"相邻 N 个文件"。

#### ZIP 头解析

- 单次顺序读中央目录（CD）即完成列表（NAS 随机读 → 顺序读，万级条目分钟级 → 秒级）；
  ZIP64 支持：offset/size 超 32 位时的扩展字段解析。CD 逐字段偏移曾写错 6 处的修复叙事
  见 **[DEVLOG §1.2](../架构落地开发/01_大包性能专项.md)**。

### 11.2 打开与列表：后台化 + 虚拟化

#### 后台打开（OpenJob + 代数号）

- 打开/列表解析全部移入后台线程，UI 显示"正在打开… x%"，不再冻结。
- **代数号（generation）防错位**：用户快速切换压缩包时，旧任务完成回调不得套用到新包上——
  每个任务携带递增 gen，主线程只接受 `gen == 当前` 的结果，旧的直接丢弃。

#### 行列表虚拟化（egui 万级条目不卡的关键）

**设计**（三层）：

1. **行数据缓存**：`list_rows: Vec<Row>`（idx + 文件名引用）只在触发条件变化时重建
   （打开 / 搜索过滤 / 切标签 / 配置重载改排序或扩展名分类 / 评级筛选），不每帧重算。
   早期版本每帧对万级条目做 clone + format + to_lowercase 过滤，UI 直接卡死——
   **即时模式 UI 不等于可以每帧重算业务数据**。
2. **虚拟化渲染**：`ScrollArea::show_viewport` 只渲染可视行 ± 3 行（overscan 防滚动露底）。
   用 `skip_ahead_auto_ids(start_row)` 保持 widget Id 稳定（否则每帧 Id 漂移，选中态/悬态错乱）。
   内容区总高度 = `set_height(总行数 × step)`，让滚动条比例正确。
3. **行高实测反馈**：首帧用估算行高（18px）渲染，实测首行真实高度后反馈修正——
   避免 DPI 缩放（125%/150%）下估算与实际不符导致的行间缝隙或重叠。

**踩坑点**（四坑：usize 下溢 / 行高不均 / scroll_to_rect 坐标系 / 每帧重算，
每条均有回归测试钉死）与**多帧测试方法论**（`ctx.run_ui(RawInput)` 手动喂事件
序列跑 100+ 帧复现跨帧时序 bug）见 **[DEVLOG §1.4/§1.5](../架构落地开发/01_大包性能专项.md)**。

排序默认值的设计依据（实测 7-Zip 打包无视添加顺序强制按字典序写入）：
`ui.sort_files` 默认 false——包内顺序 = 固态包物理码流顺序，预取最优；
true = 自然序（数字段按数值 1/2/10）供漫画/图集场景。**目录模式强制自然序**
（不看该配置）：本地文件直读无解压代价，排序不影响预取物理邻接性，纯观感
收益。排序实现预生成小写键，比较器内不做 to_lowercase 分配。

### 11.3 解压进度 UX：顶栏 → 媒体区覆盖层

- 顶栏一行放不下长文件名（截断、进度条看不见）→ 进度信息移到媒体区居中覆盖层。
  原版两阶段进度（跳过前置文件 = Spinner + 字节 / 写文件 = 字节进度条）在 solid
  预取常态化后失真："跳过"其实是解码丢弃、"写文件"混着目标与预取目标，字节数与
  用户实际等待的落点对不上 → 升级为**五段协议**（✅ 已落地，`vfs::ExtractPhase`）：

  进度回调统一签名 `progress(phase, cur, total)`（`total = 0` = 无定比分母，UI 走
  活动指示；三格式 VFS + VarTidy 全量适配）：

  | 段 | 语义 | 分段判定 |
  |---|---|---|
  | `Locate` | 解码区起点 → 目标定位中 | total 恒 0，UI 显示 spinner |
  | `SkipUp` | [起点, focus) 区间的**非目标**条目（solid 流不可跳，解码丢弃） | 条目 idx < focus_idx |
  | `Upstream` | 同区间的**目标**条目（上游免费区预取顺带落地） | 目标 idx < focus_idx |
  | `Target` | focus 本体写入 | idx == focus_idx |
  | `Downstream` | focus 之后到批末的整段流：目标落地**与段内非目标流经字节都计入**（搜索过滤/标签页隐藏/缓存命中条目夹在批内目标之间是常态） | idx > focus_idx |

  定比总量的口径（防分母虚大导致 bar 永远到不了 100%）：
  - RAR：`[0, 最后一个目标下标]` 全条目按 focus 分段累计（单流全量定比）；
  - 7z：只计**本轮解码 folder 内 [folder 首条目, 该 folder 最后一个目标]**——folder
    解码到目标解净即停（真暂停驻留，见 11.4），其后的条目不会流经，不计入；
    批边界唤醒续解（新目标仍在同一 folder 顺流落地）时旧段总量/游标失效清零，
    `(cur, total) = (0, 0)` 走 UI 活动指示，下一轮重规划恢复定比；
  - 开工协议：先发 `Locate(0,0)`，再发各非零段 `(0, total)` 画 bar 骨架（UI 据此区分
    "定位中"与"解压中"）；
  - 非目标丢弃用计数 sink（`PhaseSink`）按 4MB 粒度上报；目标写盘按
    `(段内 base + 已写字节, 段总量)` 上报，跨 folder 连续累计。

  UI 呈现（`ExtractJob.phases: [(cur, total); 5]`，按 `phase as usize` 直寻）：
  - 覆盖层（目标未落地时）：总进度条（Σcur/Σtotal）+ 三条并行分段小 bar
    （跳过前置文件 / 上游预取落地 / 目标写入，total > 0 才画）；全段 total == 0
    （定位期）→ spinner，并叠加**跳过提示**：会话线程在每个非目标条目消费边界
    短锁刷新 `SessionState.skip_note`（`(下标, 条目名, 大小)`，目标落地/批边界
    驻留清空，绝不跨 io::copy 持锁），UI 转圈时读它显示"正在定位…跳过
    （<大小>）"+ 换行路径（目录主题蓝 / 文件名主题琥珀，自动换行完整可见）
    ——solid 流跳过大视频也是真解码（每目录末尾的视频是定位耗时
    主力），无比值期不再是黑箱转圈；
  - 目标落地覆盖层消失；顶栏固定槽位 mini bar（140×6 + 2 字段名前缀）画**当前
    活动段**——五段顺序推进，只画 Downstream 会在跳前置/上游预取阶段长时间停 0
    （用户误以为卡死）；活动段 = 倒序第一个 cur>0 且 total>0 的段（后段开工说明
    前段完成），hover 显精确字节进度。无比值可画时（定位 `Locate(0,0)`、段骨架
    `(0,total)`、真暂停唤醒续解段游标清零后 `(cur,0)`）兜底显最近上报段名 +
    spinner 活动指示（`ExtractJob.active_phase`，进度覆盖语义即当前段），不再留白
    ——实测无条期被用户误读为"卡在定位"。目标落地后这是预取进度唯一可见处；
  - 快路径（zip 流式 / 目录模式）与 VarTidy 只报 Target 段，语义自然退化。
- **防闪烁宽限期**：正在播 A 时切到需解压的 B，超过 `ui.extract_overlay_delay_ms`（默认 500ms）
  仍未解完才停止绘制视频帧并显示覆盖层（render API 下整个窗口只有 egui 一个平面——
  该帧 PaintCallback 不提交画面，覆盖层即自然露出；历史 wid 方案时代须 `ShowWindow`
  隐藏 mpv 原生子窗口，因 mpv 子窗口永远盖在 egui 之上）；
  500ms 内解完则画面从未中断——快速路径零闪烁。这是"延迟隐藏"而非"最短显示时间"：
  后者会人为拖慢快速解压。
- 预取场景（目标 == 正在播放条目）永不遮挡画面，顶栏弱色短标记即可。
  - **消息必须驱动续帧**：解压进度走通道 + 每帧 try_recv 排空，而 egui 只在有输入
    或 repaint 请求时产帧——任务活跃时必须 `request_repaint_after(100ms)` 定时续帧，
    否则图片/静止画面下消息积压无人消费，顶栏冻结在最后一帧（假死）；视频常播的
    mpv 持续重绘会掩盖此问题。
- 顶栏短标记"后台解压中…（剩余 N 项）"（N = `j.pending.len()`）**常显**——只要有
  解压任务就显示：keep 回看上游缓存时能看到原窗口剩余量，等待新文件时与媒体区
  覆盖层信息重复无妨（一个短数字，不构成干扰）。

### 11.4 解压会话化：extract_batch 整批快照 → 持久解码会话（extract_session）

> 背景：extract_batch 是「整批快照」模型——UI 启动任务时一次性给全目标清单，用户跳到
> 批外条目只能取消整个任务重起：解码线程销毁重建、7z 目标 folder 从头重解、解到一半的
> 前置数据全部白付。频繁随机跳看（固态包最痛的场景）下，每次跳转都重付一轮定位成本。

**设计**：UI 与解码线程之间改为**共享会话**——`SessionState { targets: HashMap<名字, (下标, 落盘路径)>, focus, alive, gen }`（`SharedSession = Arc<Mutex<..>>`，vfs/mod.rs）。解码线程循环消费会话，**批解净后真暂停驻留而非退出**（见下「批边界真暂停」）；UI 任何时刻持锁改写目标集，**跳转永不取消解码流**：

```
UI 侧（任意跳转）        解码线程（每轮规划）
targets.clear()          规划轮：targets 空？
+ 写入新批 + focus         ├─ 是 → 原地驻留（50ms 分片睡眠查新目标/cancel）
同锁读 alive：             │        直至 UI 重定向写入新批或 cancel 切包
  true  → 复用线程/通道      └─ 否 → 按目标分组规划，逐组解压
  false → 置 true + spawn      落地一个目标 → 持锁 remove + 快照 → 锁外回调 file_done
                          批解净（本 folder 清且整会话无目标）→ 条目边界真暂停
```

**协议的原子性要求**（三处必须各自在**同一次持锁**内完成，防竞态）：

1. 线程侧「批边界/规划期的 targets 判定（是否为空、是否跨 folder）」与取消检查同锁——
   否则 UI 正在写新批的窗口期线程误判空转驻留或误中断回外层（原「判空置 alive=false
   退出」路径已被驻留等待取代，误退出丢目标的竞态随之消失）；
2. UI 侧「写目标 + 读 alive + 需要时置 true」同锁——否则误判线程存活（实际已随
   cancel/出错退出）而不 spawn，新目标永远没人解；
3. 落地条目「remove + 状态快照」同锁且 remove 先行——防同一文件重复落地。

另：file_done 回调必须在**锁外**调用（std::Mutex 不可重入）；回调内再锁 session 是合法且
必要的——动态追加目标就靠它（见测试 `session_dynamic_targets_chain`：回调内链式加目标，
单次调用解出全部四个）。

**7z 实现**（sevenz_vfs.rs）：外层规划轮把 targets 按所在 folder 分组（BTreeSet 保序），
**focus 所在 folder 抢道排到 order[0]**——用户正在等的最先落地；逐 folder 仍用 BlockDecoder
直达（11.1 的 folder 直达不变）。每解一个条目持锁取三元组快照 `(是否目标, focus 漂移, folder 已清)`：
**漂移**（focus 移到了别的 folder 且仍在 targets 中）→ 立即中断当前 folder，外层重排后从新
focus folder 继续；被中断 folder 在后续轮次从头重解自愈（非目标条目只解码不落盘，重解成本 =
folder 前缀，远小于跨包重起）。无进展保险：一整轮零落地且未发生中断 → 对比 `gen`（会话
重定向代数，UI 每次重写 targets 同锁自增；解码线程每轮规划起始快照 round_gen）——gen 已变
说明期间 UI 换过目标，本轮零落地属正常，重新规划续跑（如重定向到已落地缓存项的
收尾轮——targets 已清空则转入驻留等待，见下「批边界真暂停」）；gen 未变才是真无进展 →
`Err(Archive)`（防脏目标让线程空转，UI 据此报错并回收）。

**批边界真暂停（✅ 已落地）：顺序浏览零前缀续解**

- **动机**：真暂停前 targets 解空线程即退出，用户顺序浏览（点 100 预取到 299，看完逐个
  点 101、102…）时每次切换都重启新批——重新找 folder 起点 + skip 重解前缀。解压速度远
  快于阅读速度，反复空烧 CPU/IO。
- **机制**：BlockDecoder 的解码位置不跨轮保留，且 `for_each_entries` 回调一旦提前返回
  Ok(false) 即耗尽、无法恢复——真暂停只能在**回调内阻塞**实现。整会话目标解净（本
  folder 清且其它 folder 无目标）时在**条目边界**调 `pause_at_batch_boundary`：50ms 分片
  睡眠轮询 targets/cancel，不持锁睡眠（唤醒延迟 ≤ 一个分片）。解码器与解码位置全程
  活着：纯 sleep 零 CPU、零缓存消耗、位置贴着浏览点。
- **唤醒分流**（UI 重定向写入新批后自动醒来）：
  - 精判口径（历史教训：旧判定"targets 含任何非本 folder 条目即中断"过粗——下游
    收集允许跨 folder，新批尾部常带下一 folder 头几项，会把本 folder 顺流可及的目标
    连带打断重排）：本 folder 解码流**身前**（idx > 当前条目）仍有目标 → Ok(true)
    顺流续解，从当前位置继续解码，流过即落地，**零前缀**——跳到 1000（已缓存、
    1001 未缓存）的成本 = 当前位置 → 1000，严格优于旧路径的 folder 从头重解；
    folder 解完后外层按剩余 targets 重排，自然过渡到其它 folder；
  - 身前无目标（目标全在解码流身后——回看抢道，或全在别的 folder）→ Ok(false)
    中断本 folder 回外层重排（focus folder 抢道，跨 folder BlockDecoder 直达，
    即既有漂移中断路径）；
  - 上游未命中点击走 folder 轮次重启（外层重排从头解该 folder），成本与真暂停前持平。
- **会话退出只剩两条路**：cancel（切换压缩包）与出错。规划期空目标同样驻留等待
  （原「判空退出」路径整体移除）。
- **批完成语义拆分**：7z 不再发 `ExtMsg::Done`——线程驻留后「批完成 ≠ 会话退出」，UI
  由 `pending` 清空自行判定批完成并置 `ExtractJob.idle = true`（顶栏转「解压会话驻留中」
  弱标记、覆盖层与等待遮罩随 idle 关闭、去重早退豁免 idle 任务）。RAR 未实现真暂停
  （仍判空退出并发 Done，UI 以 idle 标志防重）——已知不对称，RAR 会话仍是「整批
  快照后退出」语义。
- **唤醒续解的进度显示**：旧段总量/游标失效清零，`(cur, total) = (0, 0)` 走 UI 活动
  指示（11.3），下一轮重规划恢复定比。

**RAR 实现**（rar_vfs.rs）：单次 processing 遍历内动态消费 targets（skip 非目标、extract
目标）；目标在游标上游（upstream）→ `PassFlow::Restart` 重启遍历——unrar 无 folder 直达，
重启要重付前缀，但会话仍免掉线程/通道重建与 UI 侧任务状态错乱。候选轮/Restart 双层循环
（重启上限 64）+ 连续两轮零落地的无进展保险。

**UI 统一重定向路径 = 滑动窗口**（ui.rs `start_extract`）：**R3 零动作守卫先行**——锚点已缓存
（位图命中且磁盘 exists 复核通过）→ 纯 UI 更新立即返回：不组批、不重定向、不动 focus、不起
预取会话。预取全部变为"翻到未缓存项才触发"的搭车福利：停留已缓存区后台零活动（会话驻留或
按原计划继续解上一批），逐出导致的位图回退（点已缓存锚点、窗口却含被逐出项）也不会触发无谓
重定向。锚点未缓存才组批：`compute_batch` 以 focus 为中心重算会话窗口（目标 + 下游预取
prefetch_downstream_mb + 上游顺带落盘段 prefetch_upstream_max_mb——上游不是"向上游
取够预算"的独立预取，是定位流推进的顺手落盘伴随量，max 只是上限非目标（实取以免费区
大小为准，见 11.1）；预算字节含已缓存项 size（R1），窗口随锚点整体滑动且被上一批已解
区域顶住），持锁替换 targets + focus + gen 自增。窗口是
**全量重算**而非增量平移：每次组批都按磁盘落地状态重算（落地即出窗但占预算额度、预算内补
新），因此既会随连续观看向下游滑动，也会在跳回未落地处时整体回移到该处——窗口语义 =
「用户接下来可能看的、还没解好的工作集」。**窗口随用户滑动**：连续观看时每次组批都对齐
当前位置，跨过窗口尾界无感续解（不必等整批重解）。

**锚点只向下游推进不回退**：focus 的语义是**解码抢道锚点**（上次重定向写入的目标下标），
仅解码线程消费，与 UI 播放高亮（`App::playing`）零耦合。R3 下点击已缓存项（无论上游回看
还是下游翻页）零动作——锚点纹丝不动、后台不受干扰；只有**点到未缓存项**才重定向滑窗并
推进 focus。原 keep 分支（回看判定：点击项在锚点上游则完全不碰会话）与"整窗已落地"分支
均被 R3 零动作守卫统一覆盖（两者前提均为锚点命中）。零动作仅切 UI 侧 job 字段
（entry_idx/dest/entry_name）：FileDone 不切画面、批完成补播条件（playing != entry_idx）
不成立，画面稳定停在播放项；pending 不动（"剩余 N 项"如实反映后台）。重定向路径 pending
必须重建——旧批未落项已不在 targets 里永不落地，残留项会让批内切换误判。cancel 标志只剩
切包时置位（终止解码线程，会话随旧包丢弃）。

**收益**：随机跳看不再反复销毁/重建解码线程与重付 folder 定位成本；顺序浏览批边界
真暂停零前缀续解（新目标在当前 folder 内时连 folder 重解都省掉）；focus 抢道保证「正在
看的」优先落地；缓存命中与后台预取并行不悖；窗口随 focus 滑动，连续观看无批尾等待断崖。
VarTidy 仍走 extract_batch——一次性整批快照正适合 CLI 场景，不引入会话复杂度。

**测试**：解码线程侧 5 个单测（生命周期/复用抢道、空目标驻留由 cancel 收尾、回调链式
追加目标、focus 漂移中断自愈、gen 救回零落地轮——全部以 `run_session_until_drained`
驻留语义驱动，targets 解净后线程不退出、由 cancel 收尾断言 `Err(Cancelled)`）+ UI 层
滑动窗口冒烟测试（模拟用户批内来回跳动，覆盖 keep/重定向/磁盘降级/批完成驻留全分支，
终态断言会话存活驻留 + job idle 置位）——断言明细与跳转链设计见 **[DEVLOG §5](../架构落地开发/05_解压会话化回归测试.md)**。

### 11.6 文件列表高级搜索：语法树 + 预编译 + 防抖（✅ 已落地）

> 代码：`src/search/engine.rs`（语法速查表：[serach.md](../../serach.md)，UI 内悬停 "Search:" 标签同源）。
> 搜索从子串过滤升级为表达式过滤，风险是万级条目大包上每键全量重过滤；
> 三项措施把开销压回与旧子串搜索同量级。
> 附带：搜索框聚焦时弹出最近查询（`src/search/history.rs`，持久化到 config.toml
> 同目录 `search_history.toml`，最多显示 15 条 / 存 50 条，失焦/回车记录）。

**语法**（优先级从高到低：`"精确短语"` → `!` → 空格 AND → `|` OR；`<>` 分组改变优先级）：

| 写法 | 含义 |
|---|---|
| `a b` | AND：同时包含 |
| `a\|b` | OR：任一包含 |
| `!a` / `!<a\|b>` | NOT：排除 |
| `"a b"` | 精确短语（含空格，不做通配展开） |
| `*` / `?` | 通配：多字符 / 单字符（不跨空白） |
| `<a\|b>` | 分组 |

**实现：两段式编译**
- **Lexer**：引号短语先行提取为占位符（`\x00N\x00`），剩余按特殊字符（`| ! < >` 与空白）分词，空白即隐式 AND
- **递归下降 Parser** 产出语法树 `SearchNode`（`Include` / `Pattern` / `Exact` / `Not` / `And` / `Or`）
- 求值 `eval_node` 对条目名递归布尔求值；**空树匹配一切**（空输入与纯符号输入均如此，保持旧"不过滤"行为）

**性能三件套**
1. **通配符预编译**：含 `* ?` 的词在解析期一次性编译 `(?i)` 正则入 `Pattern` 节点（`word_node`），
   逐条目只跑 `is_match`。正则编译次数 = O(查询词数)（每键 1 次解析），而非朴素实现的
   O(条目数 × 词数)——后者是万级条目每键几十 ms 卡顿的主因。pattern 全字符转义
   （`regex_escape`），单一量词无嵌套，无灾难性回溯；编译失败降级字面子串（兜底保险）
2. **一次解析多次求值**：`rebuild_view` 每次重建只 `parse_query` 一次，整棵树复用遍历全部条目
3. **防抖**（`ui.search_debounce_ms`，默认 200，0 = 本帧立即）：输入变化只置 `search_dirty`
   记时间戳，停顿满时长才 `rebuild_view`（见 11.2，产 `list_rows` 缓存）。egui 按需重绘下
   停手后无人唤醒到期帧——未到期时 `request_repaint_after(剩余时长)` 预订；`rebuild_view`
   入口统一清 dirty，打开 / 切标签 / 存配置等其它入口调用后不残留重复触发

**输入中间态容错**（打一半不报错、不锁列表，降级为"已能解析的部分"）
- 悬空 `!`：丢弃该修饰符，已收集词保留；未闭合 `<` / `"`：读到串尾自然收束
- 纯符号输入（`!`、`|`、`>`）→ 空树 → 匹配全部
- 自动切标签页判定用原始输入 `search.trim().is_empty()` 而非查询树判空：`!` 这类
  无法成词的输入同为空树，用后者会在输入过程中误触发切页

**与既有机制衔接**
- 搜索框聚焦时播放器快捷键整体让位（nav.rs），空格 / `!` / `<` / `|` 等语法字符安全输入；
  Ctrl+A / Ctrl+Q（全选 / 清除全部选中，成对）同理让位给文本框原生收键
- 过滤仍复用 11.2 的虚拟列表缓存链路，搜索只改 `view` 索引与 `list_rows` 内容

### 11.7 预取批的物理序原则与缓存命中位图（✅ 已落地）

> 代码：`ui/extract.rs compute_batch`（批构成）、`cache.rs`（scan_cached /
> evict_if_needed）、`ui::ArchiveState.cached`（位图）。本节记录批构成的两条
> 铁律与命中判定的位图化。

**铁律一：预取批 = 物理序 + 全量落地**

- 下游批从 `entry_idx+1` 沿**包内物理序**收（上游免费区 `locate_start..entry_idx`
  同样物理序）：solid 流不可跳，批内条目物理连续 = **每个解码字节都落缓存**，
  夹缝浪费归零——这是预取设计的原点。上游批是定位流推进的顺手落盘伴随量
  （流过才落、预算只封顶不凑满，见 11.1），不是向上游凑够预算的独立预取。
- **不看 view**：view 序在排序（`ui.sort_files`）/搜索过滤下 ≠ 物理序，批会物理
  散布、跨 solid 块解码，夹缝浪费不可控。也不做 view 可见过滤：夹缝条目（搜索
  过滤/标签页隐藏/非媒体文件/缓存命中）解码本来就要穿过，可见过滤只省磁盘——
  磁盘成本由 LRU 上限兜底、预取 size（`extract.prefetch_*_mb`）用户自控，
  过滤判断纯属多余。历史版本曾按 view 序 + 可见过滤组批，复盘见 DEVLOG。
- **排序开启也不禁用下游预取**：自然序 ≈ 物理序（7-Zip 打包本就字典序），
  命中即赚一次免解码；不命中的最坏情况（点击未落盘项 → 会话废弃重启）与
  不预取**完全等价**，无额外代价——空间换时间，seek 代价大的 solid 包上
  期望收益为正。
- 上游/下游批天然不重叠（下游从 `entry_idx+1` 起、上游止于 `entry_idx`），
  无需去重；`is_dir` 跳过；已落地条目跳过（不入批不落盘）但**占预算额度**（R1，
  见 11.4——窗口被已解区域的缓存字节顶住，永不越过批起点）。

**铁律二：缓存命中判定 = 位图，零系统调用**

- 旧判定逐条目 `std::fs::metadata`（万级条目批扫描 = N 次系统调用；cache.dir
  配到网络盘时代价显著）→ `ArchiveState.cached: Vec<bool>`（下标 = entry idx）
  O(1) 查询。
- 生命周期（四个钩子，全部 UI 线程，无并发问题）：
  1. **建图**：打开包 `scan_cached` 一次 readdir——解析 `{archive_id}_{idx}_`
     文件名前缀 + `DirEntry` 附带 metadata 尺寸校验（零额外 open）；**不按扩展名
     排除临时文件**——`~tmp_` 前缀与 `{aid}_` 解析天然不冲突、条目本名叫 xxx.part1
     （分卷）的落地缓存扩展名就是 part1（合法缓存必须收下），启动残留由
     `cleanup_partial` 清掉，扫描时不会遇到临时文件；
  2. **置位**：`ExtMsg::FileDone`（VFS 侧 rename 成功才会发）→ `cached[i]=true`，
     位图可信的根基是临时文件 + 原子改名协议；
  3. **清位**：LRU 逐出 `evict_if_needed` 返回被删 `(archive_id, idx)` 清单；
     设置面板「清空缓存」→ `fill(false)`；
  4. 换包清旧缓存（`clean_on_switch`）：旧包位图随 `ArchiveState` 销毁，无需操作。
- 失真面收敛到一种：绕过程序手删缓存文件 → 播放走既有错误路径。与旧 metadata
  方案的 TOCTOU（判定后被逐出）等同，不新增风险。
- **exists() 兜底校验（✅ 已落地）**：实测出现位图失真（列表显示 ✓ 但文件不在盘上）
  ——根因已定位：**滞留 FileDone 复活已逐出条目**（发送"rename 成功"与 UI 消费之间
  有通道积压窗口，期间新批 evict 可能删掉该文件）与双实例共享缓存目录的外部删除。
  修复两层：FileDone 置位前 `dest.exists()` 复核（根因消除）；命中判定加 `exists()`
  兜底，文件缺失按 miss 走解压路径、块外回写清位 + warn 日志（缓存位图失真），单次
  失真自愈不累积。开销只在命中路径多一次 exists 系统调用，miss 路径（多数）零开销。
- 白送能力：文件列表行前缀**对勾 ✓**（弱化灰，同多选 S 的前缀写法——"已缓存"
  三字太宽会挤压文件名/破坏虚拟化等高前提，单字母 C 语义不明；✓ U+2713 在
  微软雅黑字库内）= 该条目已落地点击秒开。
- **覆盖面**：凡走解压会话落地缓存的场景都置位——solid 包滑窗批（含预取）与
  非 solid RAR / 非 solid 7z（AccessMode::SingleFile 单条目点击解压）共用同一条
  `extract_session` spawn 通道，FileDone 统一置位。zip（FastSeek 流式直读，
  文件不落地）与目录模式天然无缓存，位图恒空、✓ 不显示，符合事实。
