## 6. 图片预览模块

### 6.1 定位与实现决策

与视频播放并列的 VFS 消费者。早期与视频统一走 mpv loadfile（一条链路零成本复用
VFS/缓存/翻页）；**现已迁移至 image crate 解码 + egui 纹理直显**（13.4：翻页零延迟、
缩放平移、动图逐帧播放、预取对动图生效），mpv 降级为解码失败时的回退路径。

渲染层面：早期 mpv 以原生子窗口（wid 嵌入）盖在 egui 之上，形成双平面，引发一系列
窗口叠放绕路（见 11.3 历史、13 迁移动机）；**现迁至 mpv render API 后整个窗口只有
egui 一个平面**，视频/图片帧经 PaintCallback blit 进 egui 画布，覆盖层/弹窗/提示
天然盖在画面上，无需任何窗口操作。

### 6.2 数据流

```
选中图片 → ZipVFS 流式（zvf://）或固态包后台解压 → 缓存文件
        → image crate 解码 → egui 纹理直显（静态图 / GIF·动画 webp 动图逐帧，13.4）
        → 解码失败自动回退 mpv loadfile（旧链路保留为兜底；回退过的条目直接走 mpv）
        → PPT 式自动翻页（ui.slideshow_secs 间隔，空格/播放按钮开关）
```

### 6.3 功能与交互

| 功能 | 说明 |
|---|---|
| 翻页 | PgUp/PgDn、←/→ 切换上/下一个；滚轮在媒体区悬停时**模式感知**——视频或图片 fit 态 = 翻页（`ui.wheel_switch_secs` 节流），图片缩放态 = 锚光标缩放（缩小触底自动落 fit，13.4 交互）；文件列表区滚轮是正常滚动列表，不切换 |
| 动图 | GIF / 动画 webp 逐帧预解码 + egui 定时切帧（13.4 第 4 步）；webp 经 `has_animation()`（VP8X ANIM 位）先验分流——静态 webp 无 ANMF 块 `num_frames()==0`，盲走逐帧解出空集误报失败（实测踩坑），故静态走单帧 decode |
| 放大细节 | 两档纹理按屏幕密度（ppp）适配（13.4）：基础档 ×ppp 进 tex-lru（GPU 纹理缓存 LRU，翻页即原生密度直出）；深放大（zoom×ppp>`image_full_threshold`，默认 2.0 即越过 244% 滚轮档（死区防临界抖动，195% 档实拍 A/B 无差））后台解 full 档 ×ppp×3（封顶 12288 + 像素预算 100MP、无 mipmap 直采，SIMD Lanczos3 免二次解码 orig-lru 原图缓存，`image_full_sharpen` 默认开（amount/σ/降噪可调，降噪算法双边/导向可切换）：放大前在原图分辨率降噪 + unsharp mask）无缝换画；100% = 1 纹素:1 物理像素（zoom=1/ppp）零重采样最锐点 |
| 像素探针 | Alt+左键取点：十字标记 + 悬浮信息（原图坐标 x/y + RGB + YUV(BT.601)），机制与限制见 6.6 |
| per-file 显示对比度 | W=增强 / S=降低（每步斜率 ×1.25，OSD 显示倍率，会话内按当前文件记忆、不进 config）：绕固定锚点 127.5 的线性映射 `out=(v−127.5)×s+127.5`——黑位/白位不动，无提亮"发灰"问题（初版 gamma 幂律提亮抬黑位被否决）。三链路分治：纹理图走 imgview LUT（orig-lru 原图毫秒级重建 + 直方图重算，步数上限 ±6）、视频/raw dump/mpv 回退图走 mpv `contrast` 属性（c=25n，属性域 ±100 容 ±4 步）；探针读原图不经 LUT。多图对比视图的 W/S 见 16.6 |
| 自动播放 | PPT 式自动翻页，间隔 `ui.slideshow_secs` 可配 |
| 直方图 | Ctrl+H 开关，媒体区左下角覆盖层（亮度填充 + R/G/B 折线，见 6.5） |
| 分类 | 视频/图片标签页按扩展名分栏（config.toml `media.*_extensions`） |

### 6.4 预留扩展：图片专属纹理浏览器（render API 已落地 ✅，落地方案见 13.4）

render API 迁移完成后，解锁"图片不走 mpv、直接解码进 egui 纹理"的专属看图路径：

| 能力 | 方案 | 相对 mpv 路径的收益 |
|---|---|---|
| 零延迟首帧 | image/zune-image 解码 → `ColorImage` → egui 纹理直显 | 消除 mpv loadfile 初始化 50~200ms（建 demuxer/GL 管线），翻页即显 |
| 缩放/平移 | 纹理 UV 变换（滚轮缩放锚定光标、拖拽平移），纯 egui 交互 | mpv `video-zoom/pan` 参数链路不再需要，交互跟手 |
| 解码器覆盖 | PSD/HEIC/AVIF 等专用格式接解码库走同纹理路径 | mpv 不支持的格式不再缺位 |
| 动图 | GIF 逐帧解码 → 定时更新纹理 | 与视频共用 PaintCallback rect，暂停/单帧步进自然实现 |

图片纹理路径与 mpv 路径并存（按格式/体积路由），VFS 层零改动——两者只是同一
VirtualFile 流的不同消费者。

### 6.5 直方图（Ctrl+H）

**定位**：图片显示的只读旁路消费者——不在打开/播放通路上，Ctrl+H 才发起，
随覆盖层关闭即弃。开关是纯状态翻转，未播放时按下无副作用。

**数据流三分流**（UI 编排层按当前条目分流，见 [panels.rs](../../src/ui/panels.rs)
`paint_histogram`）：

| 当前条目 | 直方图来源 | 说明 |
|---|---|---|
| 标准图片（纹理直显） | imgview 解码 worker 顺手算 | O(像素) 一遍被解码耗时掩盖；静态图全图 / 动图首帧；随纹理进 LRU 同生命周期 |
| raw dump（mpv dump 播放） | rawdec `HistService` 按需软解第 0 帧 | mpv render API 路径 GPU 侧无 CPU 像素；软解复用 `decode_raw_frame` 同一条移位/转换链——直方图与屏幕显示逐位一致；只算直方图不传纹理 |
| 标准视频 / mpv 兜底图 | 无 | 覆盖层显示"不可用"状态文案 |

**设计决策**：单图 raw 的显示路由**维持 mpv**（色彩转换 flag 感知、多帧播放/
seek、与 13 渲染架构单平面定位一致）——曾评估"已实现软解的 raw 改走软解显示"
方案并否决：显示链路不必要地改道，换不来显示收益，直方图用旁路入口即可拿到。
软解服务（rawdec）本就有 mpv 拼参与对比栏两个消费者，直方图是第三个，符合
"≥2 消费者才独立成模块"的内聚原则。

多图对比模式的直方图覆盖层（每栏缩小版、raw 栏随当前帧）见 §16.10。

**位深归一语义**：统一压缩到 0..255 而非 clamp 舍弃。raw 由软解链天然完成——
16bit 容器低对齐数据 `shift_u16_le` 左移对齐（12bit→`<<4`）+ 转换器取高 8 位，
净效果 `(v<<4)>>8 = v>>4`，全量程 0..4095 均匀映射 0..255；14bit/10bit/16bit
同理。直方图直接对解码后 8bit 像素统计，位深处理零额外代码。

**事件驱动**：覆盖层纯绘制不发心跳，随既有帧渲染；软解完成 `request_repaint`
唤醒，符合空闲态全事件驱动约束（13 专项）。

**绘制**：媒体区左下角半透明底板，亮度 = 白色低透明填充（逐 bin 三角带 Mesh，
直方图轮廓非凸不能用 convex_polygon）+ R/G/B 折线，归一化取四通道全局最大 bin。

### 6.6 像素探针（Alt+左键）

单图视图 Alt+左键取点：十字标记 + 悬浮信息文字（原图像素坐标 x/y +
RGB + YUV(BT.601)），用于像素级核对（"这两处到底差几级"）。

- **归一化坐标存储**：探针点按归一化图像坐标（uv 0..1）保存，显示时按原图
  尺寸换算——base/full 纹理切换、缩放、平移都不漂移（同一 uv 恒指同一原图
  像素）；
- **原图取样**：像素值从 orig-lru 直取（ImageService CPU 原图缓存 LRU，见
  13.4 缓存清单），非显示纹理插值——读数不随显示档位变化；原图未保留时
  （动图 / 超预放大资格的超大图 / 已被逐出）显示"原图未保留"；
- **显示**：文字全透明背景，按取样像素亮度自动黑/白字（≥128 黑字否则白字）
  + 反色 1px 阴影兜底保证任何底色可读；信息框自点击点右下偏移，超界折回；
- **清除时机**：切图（key 变化）即清。
- **raw 栏探针**：对比视图 raw 栏另按格式分流读**文件存储原值**（NV12 显示
  YUV / GRAY 显示亮度 + 位深 / BAYER 显示 2×2 块原值），走 rawdec 按需读源，
  不占 orig-lru——机制见 §16.9。

### 6.7 方向与元数据写回（EXIF Orientation / Rating）✅

EXIF 元数据为唯一真相：解码链读 Orientation（tag 274）自动矫正显示；用户
R 键旋转 / 1-5 评星只写元数据段不重写像素，写回后重解码显示与文件永远一致。

- **解码链矫正**：静态图解码后 `meta::apply_orientation(img, orient)` 应用
  T(o) 八值穷尽变换（1 恒等 / 2 水平镜像 / 3 180° / 4 垂直镜像 / 5-7 旋转
  + 镜像）；动图（gif/webp）跳过。方向值三来源：会话 override（R 键旋转不可
  写格式）＞文件 EXIF（kamadak-exif，File/Stream 源内存 buffer 解析）＞缺省 1。
  实际应用值随 `ImgMsg::Ready.orient` 回传，进 `orientations` 方向事实表；
- **R 键旋转**：`orientation_rotate(o, cw)` 方向链轮进（1→6→3→8→1），可写
  格式 little_exif 写回文件（clear override + record 事实 + `invalidate_full`
  全缓存重解码）；不可写（压缩包内/GIF/BMP/RAW/写失败）走 rotoverride 表，
  request 时快照下发 worker 覆盖文件 tag。已接受风险：旧解码 worker 迟到
  Ready 可能短暂上传旧方向像素（同 refresh_contrast 竞态窗口）；
- **评星（分格式真相矩阵 + 延迟批量写，2026-11-23 定版）**：1-5 定星 /
  Q 清除（0 键被 100% 缩放占用）。**真相矩阵，无跨格式兜底**——
  jpg/jpeg/jpe/png/webp → **嵌入式 XMP**（xmp:Rating；img-parts 0.4 容器
  手术：JPEG APP1 / PNG iTXt / WebP "XMP " 块 + XMP 文本编辑三件套——
  已有包原位替换优先、无标记 `</rdf:RDF>` 前追加独立 rdf:Description、
  清除 = 剥离 Rating 保留其余内容；WebP 简单格式无 VP8X 容器显式 Err
  不静默兜底）；tif/tiff + 相机 RAW（arw/nef/nrw/srf/sr2/arq）+ bmp +
  gif → **sidecar `.xmp`**（Lightroom 命名约定，原文件字节零改动）。
  EXIF 18246/18249 评级读取彻底删除（Microsoft 非正式扩展位，生态只写
  XMP）；`meta::rating_kind` 判定存储形态、`read_rating`/`write_rating`
  矩阵分流。**延迟批量写**：评级按键只进 `App.rating_dirty` 内存表
  （路径 → 最新值，0=清除），落盘 = 右键菜单「同步评级到文件」/ **Ctrl+S**
  （config 编辑器窗口开着时归编辑器保存，全局臂跳过）+ 退出**静默自动
  保存** + **切换目录自动保存**（打开终态汇合点排空 dirty，worker 持有
  旧目录 PathBuf 与新会话零耦合）——退出场景 Close 拦截 CancelClose
  状态机（无询问弹窗），全部带
  "ratingsync" worker 进度窗；Done 收尾 dirty 又非空 → 再启一轮收敛后
  放行 Close；同步 worker 删除文件语义：写前 `path.exists()` 检查，
  不存在 = **跳过**（不算失败、不碰任何文件含残留 sidecar，进度窗三段
  计数）。评级只动元数据不动像素，不失效缓存；压缩包内一律会话内
  （不探测不写入）；
- **可写性矩阵**：方向写回仅 JPEG/PNG/TIFF/WebP(lossless+extended)
  （`meta::meta_writable` 按扩展名分流；PNG 由 img-parts `set_exif`
  注入标准 eXIf 块替代手写 chunk 手术）；评级按上述分格式矩阵；
  压缩包内一律会话内；
- **按需评级探测（视口惰性，2026-11-23 取代一次性全量扫描）**：目录模式
  打开只登记图片条目 idx 快照 + 常驻 "ratingprobe" worker；探测批次由列表
  视口钩子按需入队——窗口 = 可见行 ±1 个视口行（≈3×视口），**mark-at-enqueue
  位图去重**（`rating_probed[idx]` 入队瞬间置位，false→true 才发送，同一
  idx 结构上不可能二次入队，单条去重 = 一次位图下标读写）；拖动穿越
  debounce（窗口稳定 200ms 才入队，拖动途中零 IO，首帧从未入队过立即入队
  头部窗口）。批次 FIFO 进 worker（App 侧无可插入的 pending 队列），每批
  按 `meta::read_rating` 矩阵读（嵌入式头部 ≤512KB / sidecar `.xmp`），结果
  mpsc 回传 `poll_rating_probe` 合并进 `ArchiveState.ratings`（会话值优先
  不覆盖）；星级筛选激活时补扫剩余未探测项（位图 no-op 天然只入新项），
  **门控 = inflight==0** 全量事实就绪才让谓词生效（防列表闪变）；压缩包
  模式不探测（会话内评级）；
- **星级筛选与删除**：图片标签页**下拉筛选**（全部/未评/≥1..≥5，收窄 UI
  宽度）进 rebuild_view 谓词（扫描完成前暂不生效防闪变）；**切换筛选即
  清空当前选中**（旧选中在新筛选下不可见，防误选误删）。删除按**选中集**
  执行：右键菜单「删除选中（进回收站）」/ Ctrl+Delete → 确认窗（数量/
  体积）→ `trash::delete` 进回收站（**sidecar 随图连带删除**，不存在则
  跳过）。典型流：筛 ≥1 → Ctrl+A → 删除。
  **下标稳定是硬前提**：删除用 `ArchiveState.deleted` 标记集剔除显示，
  不物理移除 entries——ImgKey/评级表/多选/锚点全按 entry_idx 寻址，移除会让
  后续下标整体位移、缓存纹理错位指向错误文件。正在显示的条目被删时跳最近的
  存活条目，缓存 invalidate_full（含 natives）+ img_fallback 同步清。

**键位**（图片模式）：R=顺时针 90°，1-5=评星，Q=清星，Ctrl+Delete=按筛删，
Ctrl+S=同步评级到文件；
右键菜单：删除选中（进回收站）/ 同步评级到文件（dirty 非空才可点）；
实现：`src/meta.rs`（方向读写 + 评级矩阵/嵌入写链/XMP 文本手术）+
`src/imgview.rs`（解码链 / 缓存）+
`src/ui/nav.rs`（快捷键 / dirty 记录）/ `open.rs`（扫描 / 谓词）/
`dialogs.rs`（同步 worker / 删除）/ `panels.rs`（筛选条 / 右键菜单 /
列表 ★n 前缀）。
