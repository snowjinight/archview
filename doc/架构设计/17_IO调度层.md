## 17.1 问题与定位

三类显式发起的 IO（图片 base/full 解码、后台预取、评级 XMP 头随机读）在
**同一介质**上正面撞时互相拖慢，尤其是 NAS / 机械盘：

- **目录模式 = 最重灾区**：评级探测（每文件 ≤512KB 随机头读）与大图解码
  （18MB 级顺序读）交错，实测 3s 墙钟 vs 1.7s 纯解码；
- **zip 流式快路径**：解码/预取直读 NAS 上的压缩包，多路并发随机化读头；
- 历史方案是各处**手工守卫**（extract 预取"当前张解码中不发起"单在途
  early-return、compare 的 window_busy 闸门），规则散落、口径不一、无法覆盖
  目录模式评级。

统一 IO 调度层的定位：**只决定"何时允许开工"（admission 发牌），不代理
读路径字节**。被拒绝的请求由各服务挂自己的 deferred FIFO 队列，解码完成
事件驱动逐个放行。调度器是纯计数器（原子量 + Mutex 预算快照），无线程、
无锁竞争面（单 UI 线程发牌/回执，评级 worker 只读观察）。

## 17.2 类与规则

| 类 | 覆盖 | 规则 |
|---|---|---|
| `Decode` | 图片 base/full 解码（imgdec/imgfull）、raw 帧软解、raw 直方图 | `total < io_parallel_max_num` 才发牌（total = 三类在途之和）；超出进 deferred FIFO |
| `Prefetch` | ±1 邻居预取、对比候选 | `total < max`；`prefetch_yield` 开启时须 `decode_out == 0`；`prefetch_out < PREFETCH_MAX_OUT`(=2，±1 两单元并行，读段过读闸门串行，§17.7) |
| Rating（最低优先级） | 评级探测（目录模式 XMP 扫描） | App 侧评级队列逐条派发：`total < max` 且单在途（单 worker 阻塞收单条命令，零轮询）；`rating_yield` 开启时 deferred 非空不派发（让位），关闭 = 后台扫闸门旁路 |

关键语义：

- **deferred FIFO 保序**——单图串行链"当前张 → +1 → −1"从规则自然涌现，
  代码里不再有手工名额（extract.rs 阶段二改为按序全部 `request(Prefetch)`）；
- **窗口优先同理涌现**——compare 的 window_busy 闸门删除，候选直发
  Prefetch，解码在途时 admission 自动拒绝；
- **评级 = 最低优先级占槽派发**——评级也是发牌类（占槽记账，在途占住
  一个槽位），但派发在 poll 的 deferred 放行**之后**：deferred 有解码/
  预取排队时不派发（rating_yield 闸门），在途评级文件读完让出（文件
  粒度抢占——阻塞读无法中途打断，下一项被闸门压住即可）；槽位有空
  （total < max）时评级借空槽随行（SSD 并行档扫描不再饿死，max=1 自然
  严格串行）。worker 阻塞收单条命令（channel recv），**零轮询零睡眠**，
  派发链由结果回执 + 解码完成事件共同驱动；
- **IO 判定在发牌前完成**——`request_full` 先查原图缓存（natives LRU）：
  命中 = 纯 CPU 重采样（fast_image_resize + 锐化）**零 IO，不占槽直接
  开工**（full 升级大多数情况走此路径，不该抢 IO 槽排队）；未命中 = 真
  源读才按 Decode 发牌，worker 读毕回账（§17.7 记账前移）；
- **配置**（`[io]` 节，重载即时生效）：`io_parallel_max_num`（默认 1，
  钳制 1..=16；SSD 建议 4~6）、`prefetch_yield`、`rating_yield`（均默认 true）。

## 17.3 纳管边界（用户定案）

- **纳管**：全部显式发起的解码/预取/评级读盘；
- **rawprobe 探针豁免**：3~8 字节定点直读，无介质压力；
- **mpv stream_cb / 解压会话不纳管**——不是"不能"，是"不需要"：视频/图片
  两态互斥（mpv 回调不会与图片解码并发）、解压会话本身单在途串行；
  边角：流式 zip 解码与解压会话同时跑会在 NAS 相撞，Decode 类不区分
  来源、顺带覆盖；
- **缓存/解压路径无需覆盖**：非流式解码读本地缓存（读写分离两块盘）。

## 17.4 记账口径（fail-open，§17.7 两段分离修订版）

- **槽位生命周期**：`issue` 在 spawn 时（UI 线程 admission 判定），
  `complete` 在 **worker 读毕时**（线程内回账，成功与失败都算）——解码段
  不占槽；**回执消息不再参与记账**（消息只负责结果落地）；
- `complete` 饱和下溢（`try_update |n| n.checked_sub(1)`）；
- **pending 条目携带 `io_done` 标志**（`Arc<AtomicBool>`，worker 读毕置位）：
  看门狗超时 / retain / invalidate 剔除按标志分流——`!io_done`（读段卡死）
  → complete + 移除；`io_done`（卡在解码段）→ 仅移除（槽早已在读毕释放，
  回账反而错账）；spawn 失败回账不变（worker 未起，读段未开始）；
- **评级侧**：派发即 issue，worker 读毕回账；三处回补（send 失败回滚 /
  Disconnected 补账 / 换包会话重置就地回补）改 fail-open 双记吸收——
  worker 正常读毕也会 complete，UI 侧回补只覆盖"worker 死在读段中"的
  泄漏场景，双记由下溢吸收；
- **评级侧看门狗**：worker 是阻塞收单条命令 + 阻塞读文件，文件粒度抢占的
  前提是"读会结束"——单文件卡死（NAS 断连停滞）时无边界可让，派发时刻
  `rating_inflight_since` 超 `PENDING_TIMEOUT` 无回执即回账放行（error
  日志），迟到结果照常收回合并（worker 不摘除，读返回后派发链自然恢复）；
- 双记完成的唯一残余来源：看门狗超时回账后卡死读才完成（worker 再
  complete 一次）——计数瞬时偏低只会多放行一路（fail-open），不会卡死。

## 17.5 换上下文清 deferred

排队请求是"当时的意图"，换上下文即陈旧：`apply_open_done`（换包）、
`enter_compare_with` / `exit_compare`（换模态）调 `img.clear_deferred()`；
rawdec 的 `retain()` 按存活 key 集自动过滤 deferred。

## 17.6 不变量

1. 任一时刻 `decode_out ≤ io_parallel_max_num`、`prefetch_out ≤
   PREFETCH_MAX_OUT`(2)（fail-open 双记瞬时违例可接受，下一发牌即收敛）；
2. deferred 队首不放行则队尾绝不插队（FIFO = 串行链顺序）；
3. 单 UI 线程发牌 + poll 回执；worker 读毕回账（§17.7）；评级 worker 对
   调度器只读；
4. **读段互斥**：纳管源读同一时刻全系统至多一个在飞（读闸门保证；超时
   旁路 fail-open 瞬时违例可接受）；
5. 调度器不持有 IO 本身——删掉它程序仍然正确，只是回到手工守卫时代的
   介质争抢。

## 17.7 读段串行与解码并行（两段分离，2026-11-25 定版）

> 设计提案与背景时序图见 [§18 提案文档](18_读段串行与解码并行改造.md)
> （含 IO 消费者全量盘点 C1~C12 的 IO/CPU 负载逐项拆分），落地记录
> DEVLOG §18.14。本节为正式设计摘要。

### 17.7.1 动机与模型

调度器的初衷是让远程 NAS 的 HDD 大概率连续读——**串行化"源读"**，而不是
把"读+解码"整个单元串行化（后者让 NAS 在解码期间空转、CPU 在排队期间
空转）。定版模型：

```
读段（IO）：  全局互斥读闸门——同一时刻全系统至多一个源读在飞 → NAS 顺序读
解码段（CPU）：不占 IO 槽——读毕立即释放槽位放行下一读，解码并行跑
```

翻页流水线时序（目标）：显示 N → 预取(+1) 读 0.2s → 读毕解码 1.7s 期间
NAS 已空闲并可服务 +2 的读；翻到 +1 秒出，+2 读与 +1 解码并行——2s 翻页
节奏恢复。

### 17.7.2 纳管与豁免（读闸门消费者）

- **进闸门**（读段过 `io_gate_enter()`，guard 持有期间读源、drop 放行）：
  C1 imgview base 解码、C2 full 高清（缓存命中零 IO 直接跳闸门）、
  C3 raw 帧软解、C4 raw 直方图、C5 bayer 排列探测（并入 C3 读段）、
  C6 评级头读（≤512KB）、C7 EXIF 方向（**并入 C1 一次 IO 拿全**：全量
  预读后 EXIF 与解码同吃内存 buf，消掉历史上的两次 round trip）、
  compare 动画 webp 嗅探（头部分块读）；
- **豁免**（理由见 §18.3.2）：C8 像素探针（3~8B 交互延迟优先）、
  C9 mpv stream_cb、C10 解压会话、C11 评级同步写（外部租户/显式任务）、
  C12 本地缓存路径（被动进闸门，本地读 <50ms 闸门等待被快速释放，无害）。

### 17.7.3 读闸门与超时旁路

```rust
io_gate: Mutex<()>
io_gate_enter() -> IoGateGuard   // try_lock 快路径；忙则 20ms 轮询
                                 // 等待超 GATE_TIMEOUT(10s) 旁路放行 + error 日志
```

- 解码段**不得**持有 guard（两段分离是本设计的核心）；
- **闸门挂死风险**（NAS 断连，读永不返回）：等待超时旁路 fail-open——
  退化为两读并行，好过全链冻结（与旧 max=1 卡死全链相比纯改善）；
- 闸门无优先级（FIFO 涌现于 Mutex 排队）；读段 ≤ 数百 ms，优先级由
  deferred 让位规则在槽位层面保证（I3 不变）。

### 17.7.4 max 语义与内存上界（用户决议）

- `io_parallel_max_num` **默认保持 1**：语义从"单元全生命周期串行槽"改为
  "**排队 + 读段单元上限**"——读毕即释放，解码段不受 max 约束；HDD 场景
  读段串行大概率性能更优，解码并行由读毕释放自然获得；
- 在飞解码单元自然上界 ≈ 显示 1 + 预取 2 + full 1 + 对比栏 6 + 直方图 1
  ≈ 11 个（受 UI 拓扑约束），最坏内存 ≈ 0.6GB（6 栏 24MP raw + 源字节）；
  如需硬上限再议 `decode_max_num` 配置（本轮不做）；
- `PREFETCH_MAX_OUT` 1→2：±1 两单元并行（读段仍过闸门 FIFO 串行，+1 先
  读），解码段各自并行；顺序偏好由 deferred FIFO 与 App 侧请求顺序保证。

## 17.8 现行不变量（§19 IO 代理读重构修订，2026-11-26 定版）

§17.6 的记账类不变量随发牌模型一并作废，现行不变量（正式版）：

1. **读段并行度** = `io_parallel_max_num`（读线程数；max=1 时同一时刻
   全系统至多一个源读——NAS HDD 连续读）；
2. **优先级**：读线程取任务按 Decode > Prefetch > Rating 队列序，各队列
   FIFO 保序（单图串行链"当前张 → +1 → −1"由请求顺序涌现）；
3. **解码段无调度约束**：buffer 投回后 spawn 的解码 worker 并行度只受
   UI 拓扑约束（上界 ≈11 不变，§17.7.4 内存上界结论沿用）；
4. **取消语义（分级两档，§19.9.1）**：换包/进出对比 `clear_queued`
   清两队列 + 全部占位（迟到产物按 gen/epoch 丢弃）；切条目
   `cancel_queued_prefetch` 只摘仍在排队的 Prefetch 任务 + 清其占位
   （在途不摘，读毕照常落地）；
5. 调度器持有读线程与队列——删掉它程序失去串行化，回到介质争抢
   （§17.6 第 5 条的反转：调度器从"纯计数器"变为"读线程宿主"）。
