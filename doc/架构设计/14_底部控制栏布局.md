## 14. 底部控制栏布局机制（egui 0.36）

> 完整踩坑叙事（五坑 + 字形级测量方法）见 **[DEVLOG §7](../架构落地开发/07_UI控制栏布局专项.md)**；本节只留机制与不变量。

### 14.1 目标与结构

目标三条：播放键中心恒在窗口水平中线（零手估像素、零逐帧计算）；行底到窗口底
恒 12px；图↔视频模式切换按钮组零位移。

```
Panel::bottom("controls")              ← 锚定窗口底缘；frame inner bottom = 默认2 + 10
 ├─ seekbar 槽 18px（两模式同尺寸；图片模式隐形占位，保面板高度一致）
 └─ 行带 allocate_ui_with_layout([宽, 34], left_to_right(Min))   ← 高度必须固定
     ├─ 音量组（先画，仅视频）right_to_left(Center)：数字槽 26×34 → 滑条 84×34 → ♪ 按钮 36×34
     └─ Aligner::center().bounds(Bounds::max_rect()).show_horizontal   ← 五槽对称按钮组
         [隐形48][< 48][播放 48][> 48][模式键48 / 隐形48]
```

### 14.2 播放键居中：sizing-pass 两遍布局 + 五槽对称

- **Aligner**（egui_alignments crate，与 egui 同版本锁定）：egui 官方 sizing-pass
  机制——首帧按可用宽度隐形测量内容实际宽度并 `request_discard` 丢弃该帧，次帧
  起按实测宽度精确定位；内容宽度变化（字体/DPI/按钮尺寸）自动重测。无手估像素、
  无逐帧反馈计算。居中参照 `Bounds::max_rect()`（整行矩形），**忽略行内已占用
  空间**——因此音量组先画不影响按钮组落点（顺序反转是刻意为之）。
- **五槽等宽 48 对称**：播放键两侧各两槽 → 播放键恰为组的几何中心，Aligner
  居组＝播放键中心落在窗口中线（四槽组时播放键偏 -28px，见 [DEVLOG §7](../架构落地开发/07_UI控制栏布局专项.md) 坑3）。
  视频↔图片模式第五槽一实（模式键：视频=播放模式三态 ▶I/≡/↻，图片=翻页开关）
  一隐（等宽占位），组宽恒定，切换零位移。
  更简的单遍分段备选方案见 §14.5（后续可优化）。

**视频播放模式（三态，mod.rs `PlayMode` + nav.rs `cycle_play_mode`）**——第五槽
模式键与 L 键共用同一处理，循环顺序 **Hold → List → Loop → Hold**，默认定格：

| 模式 | 行为 | mpv 侧 | EOF 时 eof_tick |
|---|---|---|---|
| **Hold 单文件播放（定格，默认；图标 ▶I 播完即停——细线 I 顶缘与 ▶ 齐平，选形见 [DEVLOG §7.6](../架构落地开发/07_UI控制栏布局专项.md) 第三轮）** | 播完停在末帧不动 | `loop-file=no`；全局 `keep-open=always` 已保证末帧定格 + 粘滞暂停 | 不推进（门控在读取 eof 之前早退） |
| **List 列表** | 播完自动切下一个 | `loop-file=no` | 推进 `play_adjacent(1, false)` |
| **Loop 循环** | 单视频无限重播 | `loop-file=inf`，EOF 恒不触发 | 天然不触发（mpv 原生循环） |

边界语义：切到 Loop 时若已粘滞末帧（`eof_reached()`），`seek(0)` + 解除
暂停复活（loop-file 不回溯已发生的 EOF）；Hold→List 若正粘滞末帧，下一帧
eof_tick 立即推进（Hold 门控早退不写 `eof_handled`）；列表末尾停住已记
`eof_handled`，切 Hold 再切回 List 不会误推进。图片模式不适用（图片有
slideshow 自动翻页），L 键与按钮对图片豁免。

**顶栏消息机制（红/绿单槽，mod.rs `set_err`/`set_notice`）**：红（error，
操作失败）与绿（notice，一次性提示）互斥单槽覆盖——写红清绿、写绿清红，
新消息覆盖旧消息，**无任何超时**。清除路径仅三条：互斥覆盖；播放入口
（`play`/`play_image`/`load_extracted`）与切换内容源（`apply_open_done`）
翻篇清双槽；任意鼠标点击清绿不清红（帧首 `any_click` 检测，用户操作了
=看过了；红色代表操作失败，不被无关点击消除）。

### 14.3 不变量（破坏即回归，对应坑见 [DEVLOG §7](../架构落地开发/07_UI控制栏布局专项.md)）

| # | 不变量 | 破坏后果 |
|---|---|---|
| 1 | 行带固定 34 高（`allocate_ui_with_layout`），不用 `ui.horizontal` | 自动高度面板的"当帧可用高度"来自上一帧面板高度，行高自流会与 Aligner 记忆尺寸形成反馈环：实测图片模式面板 55→47 压矮、行带挤到 18、按钮溢出绘制（坑4） |
| 2 | ♪ 所在 ui 的 layout 交叉轴必须 Center | egui 0.36 Button 内部文本对齐**默认继承所在 ui 的 `layout().vertical_align()`**（atom_layout.rs align2 回退）；Min → ♪ 文本在 34px 按钮内贴顶，字形上移 6px（坑5）。行带固定高后 Center 不会引发膨胀——膨胀真凶是行带不固定高，不是 Center |
| 3 | 行底间距只由面板 frame inner bottom 决定（当前 12） | bottom 面板锚定窗口底缘 + 行带是面板末元素 → 行底间距恒定、不随内容高度变化。不要用行尾 `add_space` 垫底：实测实推 7px 且位置随行内分配漂移（坑2） |
| 4 | 行内子项一律显式 34px 等高（音量组三个子项、按钮组全部按钮） | 高度不齐时交叉轴对齐差异可见；等高时 Min/Center 对矩形位置无影响，只通过不变量 2 传导给 Button 文本 |

另：egui 0.36 `Margin` 字段是 `i8` 整型（`frame.inner_margin.bottom += 10`），
写 `+= 4.0` 直接 E0277 编译错（坑1）。

### 14.4 验证方式

无头字形级测量：`Context::run_ui` 复刻行结构跑多帧，从 `FullOutput.shapes` 提取
♪/▶ 的 `TextShape`，用 `galley.rect`（文本框）与 `galley.mesh_bounds`（墨迹紧致
包围盒）对齐按钮 `Response.rect`——能测出肉眼级的 6px 回归。方法与数据见
[DEVLOG §7.6](../架构落地开发/07_UI控制栏布局专项.md)。最近一次全量回归（12px 版）：行底距窗口底 12.0、播放键中心偏差 0.0、
♪ 文本框居中偏差 0.0、两模式面板高度帧间稳定。

### 14.5 备选方案：分段布局天然居中（后续可优化）

**定位**：已评估、暂未采用的更简方案。§14.2 五槽 + Aligner 满足全部硬性需求，但
把方案锁定在"组级居中"（需预知组宽 → 双遍）的真正原因是**三连紧凑相邻**——那只是
早期视觉约定，不是需求（§14.2/§14.3 均未要求紧凑性）。放宽它即可单遍。

**结构**：行带内按比例切段，段宽只依赖 avail、与内容无关：

```
行带 [宽, 34]
 ├─ 左段 25% × 34：[<]（右对齐，贴近中段）
 ├─ 中段 50% × 34：[播放]，allocate_ui_with_layout(top_down(Align::Center)) 居中
 └─ 右段 25% × 34：[>] [模式] + 音量组（right_to_left(Center)，贴右缘）
```

- 中段居中是官方**单遍**原语：child Ui 先跑闭包排版内容、再按 layout 交叉轴对齐
  放置整块（块级 measure-then-place，`ui.vertical_centered` 同原理），无需预知按钮宽。
- 左右段等宽 ⇒ 中段几何中心 = 窗口中线 ⇒ 播放键精确居中；模式切换零位移**天然
  成立**（播放键落点与模式键/音量组无关），无需隐形占位槽。

**与现行方案对比**：

| | 现行 §14.2（五槽+Aligner） | 分段方案 |
|---|---|---|
| 遍数 | 布局变化帧双遍（request_discard），稳态单遍 | 恒单遍 |
| 额外依赖 | egui_alignments | 无 |
| 隐形占位槽 | 需要（对称/恒组宽） | 不需要 |
| < > 与播放间距 | item_spacing（8px 紧凑三连） | 随窗口宽变化（≈宽/4，1200px 窗约 276px） |
| §14.3 不变量 1-4 | 全部适用 | 全部兼容（不变量与间距无关） |

**为何暂不切换**：现行方案已通过 §14.4 全量回归，两者产出等价；切换收益是去
依赖/去双遍，代价是重趟 child Ui 的 cursor/min_rect 暗礁（坑4 近亲）+ 回归重跑。
**后续优化入口**：确定接受按钮分离观感后，改动范围 = panels.rs `controls()` 行带
内部 + 移除 egui_alignments 依赖 + §14.2 与本节对调改写 + DEVLOG 新条目 + 重跑
§14.4 回归。另有混合变体（整行区域 + 三连组块先排后放居中 + 音量组后画贴右）亦可
单遍且保紧凑，但同样需先验证 child Ui 组合行为。
