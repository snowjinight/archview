## 4. 点击状态机排查手册（start_extract 分支链与日志对照）

> 机制设计（会话化协议、滑动窗口、R3 零动作守卫）见 [ARCHITECTURE §11.4](../架构设计/11_性能优化与虚拟列表.md)；
> 本手册回答"用户每次点击后发生了什么、各自打什么日志"。排查「点了没反应 /
> 后台解压停了 / 画面跳来跳去 / 窗口被拽回去」类问题时，以本节日志关键词
> grep 日志流即可对号入座。

**两个正交变量**（所有分支日志都同时打印它们，混淆二者是多数误判的根源）：

- `playing`（`App::playing`）——**用户正在看什么**：UI 列表高亮与滚动跟随的唯一依据，
  由 `load_extracted` 在播放时写入；
- `focus`（`session.focus`）——**解码线程在解什么**：抢道锚点 = 上次重定向写入的目标
  下标，**只向下游推进不回退**（零动作分支不改写），仅解码线程消费。等待 80 解压时回看 10：
  `playing=10` 而 `focus=80`，两者不同才是正常态。

**分支判定链**（ui.rs `start_extract`，按代码顺序短路，命中即返回；R3 零动作守卫
统一了原 keep / 整窗已落地两分支——两者前提均为锚点命中）：

```
点击 entry
 ├─ ① !j.idle && j.entry_idx == entry？ ──── 是 → 静默返回【去重早退，无日志】
 │    （idle = 7z 批完成驻留：entry_idx 停在上批锚点不算"在跑"，
 │      同位重点击——位图失真降级未缓存等——须照常往下走）
 ├─ ② cached（锚点已缓存）？ ─────────────── 是 → 零动作【纯 UI 更新，不碰会话】
 │    （不组批、不重定向、不动 focus、不起预取会话——预取全部变为
 │      "翻到未缓存项才触发"的搭车福利；原 keep 与整窗已落地分支并入）
 ├─ ④ 磁盘放不下新窗口？ ────────────────── 是 → 报错返回，不起解压
 └─ ⑤ 重定向（同锁：targets ← 新窗口、focus = entry、gen += 1；复用路径
       同时清 j.idle——新批开工，清除上批的批完成驻留标记）
       ├─ 会话存活（解码线程在跑——含 7z 批完成驻留——流续跑/唤醒，cancel/通道复用）
       │    ├─ was_pending → 批内切换目标
       │    └─ 其他 ───────→ 批外会话重定向
       └─ 会话已死 → spawn 新线程（新 cancel/通道）→ 后台解压
```

判定依据：`cached` = 目标文件在盘且尺寸一致（位图命中再加 `dest.exists()` 兜底校验，
失真即清位降级未缓存，warn `缓存位图失真`）；`was_pending` = 目标在当前任务 pending 表；
`idle` = 7z 批完成驻留标志（`poll_extract` 检测 pending 清空时置位；RAR 经 Done 置位防重）。

**日志对照表**（文案与代码逐字一致，grep 左列关键词即命中）：

| 分支 | 日志开头（关键词） | 级别 | 附带状态字段 |
|---|---|---|---|
| ① 去重早退 | （无日志） | — | 连点同项时无任何输出 |
| ② 零动作（锚点已缓存） | `缓存命中（零动作）` | info | 锚点 focus / playing / 当前窗口 |
| ④ 磁盘不足报错 | `缓存目录所在磁盘空间不足` | error | 剩余/所需 GB、缓存目录路径 |
| ⑤b 批内切换 | `批内切换目标:` | info | 窗口滑动至 N 项（物理 a..=b）/ 锚点 focus 旧→新 / 切换前 playing |
| ⑤c 批外重定向 | `会话重定向:` | info | 新批 N 项（物理 a..=b），解码流续跑 / 锚点 focus 旧→新 / 切换前 playing |
| ⑤e 后台解压 | `后台解压:` | info | 目标路径 / 顺带预取 N 项 / 锚点 focus 旧→N / 切换前 playing / 窗口摘要 |
| — 批完成驻留（仅 7z） | `批完成（会话驻留）` | debug | 最后目标 / 锚点 focus / 当前窗口 / playing；会话**不退出**（真暂停驻留等新目标），alive 保持 true；下一次点击未落地项走 ⑤ 重定向唤醒续解（零前缀） |
| — 会话死亡（仅 RAR / 出错） | `会话解净空闲退出（窗口清空）` | debug | 最后目标 / 锚点 focus / 当前窗口（空）/ playing；此后缓存命中点击走 ②。7z 真暂停后**不再打此日志**（Done 已不发，批完成改由上一行承接） |

> 字段说明：`切换前 playing` = 本次点击切换**之前** `App::playing` 的值（时间维度的"前"，
> 与上/下游方位无关）——用于对照切换后画面是否如期变化。`锚点 focus 旧→新` 的"旧"是
> 本次重定向写入前的 focus（可能是 None）；`窗口摘要` = `N 项，物理 a..=b`（targets 的
> 物理下标范围 + 条目数；② 打印的是**当前**会话窗口，⑤b-⑤e 打印的是**新算出的**
> 窗口）——用来一眼看出"点击项在不在后台正在解的范围内"（LOG2 的来回重定向问题：
> 批内切换 105 项 ↔ 会话重定向 106 项恒定不变 = 没有任何文件落地）。
>
> **② 零动作守卫**（R3）——点击项已在盘即触发，无论会话死活、无论点击项在锚点上
> 游还是下游：仅切 UI 侧 job 字段（entry_idx/dest/entry_name）+ `load_extracted`
> 播放，会话 targets/focus/gen/pending/cancel 全不动。设计动机：预取是"解码流顺带
> 落盘"的伴随量，用户停留已缓存区时后台零活动——逐出导致的位图回退（点已缓存
> 锚点、窗口却含被逐出项）也不会触发无谓重定向（用户原话"除非我点到了不在缓存
> 里面的东西"）。下游预取因此只在"点到未缓存项"时随批搭车：翻页流畅性不受影响
> （未缓存项组批时解码头通常就在附近，唤醒续解零前缀）。

**零动作（②）与重定向（⑤）的本质差异**——② 是唯一不碰会话的播放路径：

| 动作 | ② 零动作 | ⑤ 重定向 |
|---|---|---|
| `session.targets`（窗口） | 不动 | clear + 写入新窗口 |
| `session.focus`（锚点） | 不动（只向下游推进） | = 点击项（向下游推进） |
| `session.gen` / `App::next_gen` | 不动 | 各 +1 |
| `j.pending`（"剩余 N 项"数据源） | 不动（后台量如实） | 重建 |
| `j.entry_idx`（批完成补播依据） | = 点击项 | = 点击项 |
| cancel 句柄 / 解码线程 | 不动 | 存活则复用，已死则重 spawn |

**落地侧**（`poll_extract` 每帧消费线程消息，注意两条**无日志**路径）：

- `Progress(stage, done)`：浮层文案/进度条数据源，**覆盖语义**（后到整体替换先到）。
  **坑（消息积压幻象）**：若图省事每帧只消费一条 Progress 就 `return`（10fps ≈ 10 条/秒），
  而线程每落地一个文件发 ≥1 条（copy_with_progress 每 4MB 一报 + 小文件首尾各报，
  879 项批 ≈ 两千多条），通道积压分钟级，三大症状连锁：① 线程早已判空退出
  （`alive=false`），浮层仍转圈"正在解压/跳过前置文件"——**积压驱动的过期显示，
  极易据此误判会话存活**；② `Done` 排在积压尾，`会话解净空闲退出` 死亡日志迟迟
  不打；③ 下一次点击未落地项走 ⑤ spawn 时整体替换 `job.rx`，整个积压连同 `Done` 被丢弃——
  死亡日志**永远**不出现，症状变得不可解释
  （实为会话几分钟前已死，见下 Done 条目）。修复：排空循环——Progress 只留
  最新一条（覆盖语义下中间态无意义），FileDone/Done/Failed 即时逐条处理。

- `FileDone(i)`：从 pending 移除；`i == j.entry_idx && playing != Some(i)` → 立即自动开播
  （**无日志**，判断依据 = 画面切换 + 日志里"后台待落地 N 项"递减）；预取项落地只记账。
  零动作（②）之后 `j.entry_idx` 是回看项，80+ 的落地不会把画面拽走——这正是零动作
  守卫的安全性来源。
  **移除后 pending 清空且 !idle = 批完成**：置 `j.idle = true`，debug 日志
  `批完成（会话驻留）`（最后目标/锚点/窗口/playing 快照）——7z 真暂停后原 Done 兜底
  逻辑移至此处执行（补播条件同下）；会话**不死亡**，alive 保持 true；
- `Done`（整批解净，会话空闲退出）：`extract = None`，debug 日志
  `会话解净空闲退出（窗口清空）`（锚点/窗口/playing 快照）——**会话在此死亡**，
  此后下一次点击未落地项走 ⑤ spawn 重新拉起解压会话并
  重写锚点。**仅 RAR 会到达**（RAR 未实现真暂停，targets 解空线程退出并发 Done）；
  7z 线程驻留不退出、不发 Done，批完成改由 FileDone 侧承接；
  兜底补播仅当 `gen == next_gen && playing != Some(entry_idx) && 文件在`
  （零动作后 playing 已是点击项 → 不触发，画面稳定）；
- `Failed`：error 日志 `解压失败: 压缩包 [..] 条目 [..] → [..]: {e}` + 弹错误框；密码
  错误（`VfsError::Password`）**不落日志**，直接弹密码框（提交后重建 VFS 重试）。

**解码线程侧**（仅两条，见 [ARCHITECTURE §11.4](../架构设计/11_性能优化与虚拟列表.md)）：

- info `7z 会话本轮零落地但检测到重定向（gen X→Y），重新规划续跑`——gen 救回：重定向
  打断后本轮剩余流零落地属正常，重规划而非误报。**看到它说明会话健康，不是错误**；
- `7z 会话无进展: 目标条目未出现在 folder 解码流中`——真无进展（gen 未变的零落地轮），
  上浮为 error `解压失败: ...`，会话已置 `alive=false`，下次点击走 ⑤ spawn 路径。

**变量速查**（日志里出现时的读法）：

| 字段 | 含义 | 写者 → 读者 |
|---|---|---|
| `playing` | 正在播放的条目（UI 高亮/滚动跟随） | `load_extracted` → 渲染/兜底判定 |
| `锚点 focus` / `锚点 focus→N` | 后者仅出现在重定向日志 = 锚点**推进**到 N | UI 重定向 → 解码线程（folder 抢道/漂移） |
| `gen`（session）/ `next_gen`、`j.gen`（UI） | 重定向代数；`j.gen == next_gen` 表示期望未被后续点击取代 | UI 同锁自增 → 线程零落地救回 / Done 兜底 |
| `后台待落地 N 项` | `j.pending.len()`，即"剩余 N 项"顶栏数据 | FileDone 递减 → 顶栏显示 |
| `窗口 N 项，物理 a..=b` / `窗口摘要` | 会话 targets（解码线程正在解的工作集）条目数 + 物理下标范围；② = 当前窗口，⑤b-⑤e = 新算窗口 | `compute_batch` 组批 → 日志观测"点击项是否在解"（窗口数恒定不变 = 零落地） |

**典型时序回放**（用户场景：看过 1-30 已缓存，跳 80 等解压，回点 10、11，再点 81）：

```
后台解压: clip_80.mp4 → D:\cache\..（顺带预取 15 项）｜锚点 focus 29→80，切换前 playing=Some(29)，窗口 16 项，物理 80..=95
缓存命中（零动作）: clip_10.mp4｜锚点 focus=80，切换前 playing=Some(80)，当前窗口 16 项，物理 80..=95
缓存命中（零动作）: clip_11.mp4｜锚点 focus=80，切换前 playing=Some(10)，当前窗口 16 项，物理 80..=95
批内切换目标: clip_81.mp4（窗口滑动至 16 项，物理 81..=95）｜锚点 focus 80→81，切换前 playing=Some(10)
7z 会话本轮零落地但检测到重定向（gen 1→2），重新规划续跑   ← 上一步重定向打断旧轮，救回属正常
（此后后台健康解压 = 顶栏剩余数递减、窗口摘要里的落地项逐步出窗；整批解净多一条
"批完成（会话驻留）"——7z 会话不退出、驻留等新目标，下次点击未落地项即唤醒续解；
画面停在 81 落地自动开播——无日志）
```

**常见症状速查**：

| 症状 | 先查 |
|---|---|
| 点了没反应 | ① 去重早退（无日志，`j.entry_idx` 已是它）；或条目被过滤（不在 view → `start == usize::MAX`，目标单独成批）；或 ② 零动作（目标已缓存，查 `缓存命中（零动作）`——正常秒开，非"没反应"） |
| 后台 80+ 解压停了 | 最近一条点击日志是 `会话重定向`/`批内切换` 且锚点回退上游？→ 正常路径下不可能（锚点只推进）；若出现需查 UI 侧意外调用。正常回看应见 `缓存命中（零动作）` 且会话不动 |
| 画面被拽走/跳来跳去 | FileDone 自动开播条件 `i == j.entry_idx && playing != Some(i)`——零动作后 j.entry_idx 是回看项不该触发；若触发说明走了重定向（查 `锚点 focus→N` 日志） |
| 顶栏剩余数跳变后冻结 | 剩余数 = `j.pending.len()`，零动作不动它（如实）、重定向重建它；冻结 + 无 `解压失败` → 线程可能真无进展（查 `7z 会话无进展` 上浮的 error） |
| 反复出现 `重新规划续跑` | 每次重定向打断一轮都可能救回一次，正常；但若**没有**任何点击日志却持续出现，需查 UI 侧是否有意外调用 `start_extract` |
| 来回点两个未落地条目疯狂 `会话重定向`/`批内切换` | 窗口摘要恒定不变（=零落地）；两点击项互不在对方窗口（上游侧未覆盖：`prefetch_upstream_max_mb=0` / 7z folder 边界 / sort 后物理距离超预算）——重定向打断解码使两边永远落地不了，见"会话死亡"前的窗口对比 |
