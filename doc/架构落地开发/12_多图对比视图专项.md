# §12 多图对比视图专项

> 对应架构章节：[ARCHITECTURE §16](../架构设计/16_多图对比视图.md)。
> 本文记动机、实现过程、守卫细节与测试；机制 / 决策 / 不变量在那边。

## 动机

用户需要把包内 2~6 张图（不同作者 / 不同参数的同类图）分栏并排对比，
同步缩放平移逐区域比对。原决策"非标文件都走 MPV"在对比场景失效——mpv
一个 core 只能渲染一路画面，多栏对比要么多实例（重、状态难同步）要么不可行。
排查发现非标 raw dump 本质是"字节序列 → 像素缓冲"的确定性转换（软解已具备：
§8 的转换器、bayer 探测、bit_shift 语义都在），图片纹理直显路径（13.4）本来
就不走 mpv——**两条非 mpv 路径合流后，对比视图统一走 egui 纹理，mpv 完全
不在场**。方案讨论与决策记录见 `PLAN_compare_view.md`（仓库根目录）。

多选入口复用 encode 批量选择的选择集（原为编码服务建立），选择语义零新增。

## 关键实现细节

### 方案 A 几何（纯函数单测钉死）

共享 zoom = 相对各栏 fit 的倍率、共享 center = 归一化图像坐标。屏幕矩形
推导：`p + center*disp = vp.center` → 中心 = `vp.center + (0.5−center)*disp`。
锚点缩放推导：锚点图像坐标 `u = center + delta/disp` 不动 →
`center' = center + delta*(1/db − 1/da)`。disp 按主栏取值，center 是共享量，
各栏自动对齐。这套数学全部抽成纯函数放 compare.rs 顶部，11 个单测逐个钉死
（大图不露边、小图归中、锚点不动、fit 底界落 None、布局映射、滑动吸附等）。

### RawFrameService 线程模型（crate::rawdec）

每请求 spawn 独立 "rawdec" 线程（`catch_unwind` 兜解码 panic，不炸 UI），
`mpsc` 回 UI 线程上传纹理。三个集合分工：

- `frames`：成功帧缓存（ImgKey → 纹理参数），**保留旧帧**——帧游标移动时
  未及解码的栏显示上一帧而非黑屏闪烁；
- `errs`：确定性失败（参数错 / 数据不足），不重试；
- `pending`：在途请求防重。`request` 幂等：pending / 已有帧 / 已 errs 均跳过；
  帧号钳制到 frame_count−1。

会话切换时 `rawdec.retain(shown_keys)` 丢弃离场栏的全部状态（线程产物由
接收端丢弃即自清）。

### bayer 软解

16bit unpacked Bayer 双线性插值：2×2 相位窗口内同色/异色通道按 1/距离²
加权。相位偏移表 `bayer_offsets` 在解码前按排列（RGGB/BGGR/GBRG/GRBG）
预计算（`[[Vec;2];2]` → 每通道 [Vec;2] 的 [x,y] 偏移），避免逐像素分支。
bayer_auto16le 先跑 `extract::resolve_auto_bayer` 探测排列再进固定排列转换。
`shift_u16_le` 与播放路径 stream_cb::ShiftReader 同语义（u16 LE 配对
wrapping_shl），12bit 低对齐数据位移逐位一致。

### source_ready 闸门（防确定性失败污染）

非流式包（7z/RAR）条目未解完时 dest 文件是半截的，此时发起解码必然失败，
且失败会被两个服务**永久记住**（ImageService → img_fallback 不再重试、
RawFrameService → errs 不再重试）。`source_ready`（File 源 metadata len ==
size）在所有解码请求入口过滤：compare_after_change 建栏、
compare_request_raw_frames、compare_tick 自愈重试三处统一过闸。

### 解压会话联动（非流式包对比）

对比会话触发解压的策略：**仅主栏 start_extract**（solid 包 compute_batch
滑窗顺带解出其它栏；single-file 包其它栏显示等待文案）。触发条件在
compare_tick 内收敛：主栏未落地 && 无密码框 && 无错误 && 进度未覆盖
→ start_extract(master)。落地后 compare_tick 的自愈段 filter source_ready
重新发起解码——落地事件不需要显式通知，轮询即可收敛。

### 防播放劫持（三处守卫）

对比与播放互斥，但解压链路完成时会"好心"补播，必须封死：

1. `play()` 顶部：`compare.is_some()` → 清 compare + clear_shown_multi +
   rawdec.retain([])（防御性：正常路径不会在对比态调 play）；
2. `poll_extract` FileDone 自动播放条件加 `&& self.compare.is_none()`；
3. `poll_extract` Done 兜底补播条件加 `&& self.compare.is_none()`。

对比会话自己触发的解压会话，其 FileDone/Done 一律不回播放——退出对比时
exit_compare → play(master) 是唯一回放入口。

### ImageService 多键驻留

单图模式缓存策略假设"同屏只有一张图"，逐出会抖掉旁边栏的纹理。新增
`shown_multi: HashSet<ImgKey>`：set_shown_multi(shown_keys) 后 cache_push
逐出候选跳过集合内键；`frame_ex(key, drop_stale_full)` 替代原 frame 路径——
非主栏传 `drop_stale_full=false`，防 full 高清纹理槽被非主栏请求逐帧顶掉。

### egui 0.36 实测差异（与 §10 的坑同类）

- `FontId::small()` 不存在 → `TextStyle::Small.resolve(ui.style())` 取字号；
- 栏内裁剪绘制用 `ui.painter_at(cell)`（painter 限定在 cell 矩形内）；
- RawFrameService / RawFrameTex 住 crate::rawdec，结构体与字段需
  `pub(crate)`，ui 层（App 字段、panels 取帧）才可访问。

## 踩坑

- **测试断言自己写错**（5 个，代码数学全对）：shift 测试输入字节序错
  （0xABC0 应为 0x0ABC）；nv12 色度全 0 时 G 最大而非最小（BT.601 下
  R/B 同减同色度偏移，G 不动）；pane_image_rect center=(0,0) 期望值算错
  （中心 = vp.center + 0.5×disp，不是 0）；bayer_offsets 用
  `Default::default()` 得到外层空 Vec，索引 panic → 必须
  `std::array::from_fn` 逐元素建 [Vec;2]；grow_window 测试把"无可追加"
  和"正常放大"写进同一 unwrap 断言，自相矛盾 → 拆两个测试。
  教训：**几何/查表类纯函数，先在草稿纸算一遍期望值再写断言**。

## 重构：raw 软解升格媒体层模块（src/rawdec.rs）

初版为单消费者 YAGNI 决策：raw 软解（转换器 + RawFrameService）只被对比
视图消费，按功能内聚放 compare.rs；而真正多消费者的部分（RawLoad 参数
解析、bayer 探测、预设校验）当时已在 extract.rs。评审后按"能力内聚"合并
抽取：extract.rs 的 raw 装载段与 compare.rs 的软解段本就是同一条 raw 媒体
链路，合并成 `src/rawdec.rs`（与 imgview.rs 平级）后模块有两个真实消费者
（mpv 播放路径 + 对比软解路径），UI 层只剩"申请帧 + 收帧"调用。

- 迁移清单：RawLoad + opts()、raw_demux_opts（App 方法改为薄委托
  `crate::rawdec::raw_demux_opts(&self.cfg, …)`，全部调用点与 ui/tests.rs
  零改动）、detect_bayer_layout / resolve_auto_bayer、全部像素转换器、
  soft_decodable / raw_frame_info / RawFrameInfo、RawFrameService /
  decode_raw_frame 及转换器单测随迁；
- 可见性整体从 pub(super) 升 pub(crate)（跨 ui 模块边界）；
- extract.rs 保留 play/poll 链路不变，compare.rs 只剩会话状态 + UI 组合。
- 教训：单消费者时按功能内聚、多消费者时按能力内聚——但两个粒度的判断
  都要在评审时显式说出来并留迁移触发线，而不是默认现状。

## 首轮实测反馈修复（webp 支持 + 键位可发现性）

实测反馈四条，两条是需求变更、两条经核实为按设计语义（用户未发现）：

1. **滚轮缩放"不生效"**：核实为按设计语义与单图模式一致——fit 态裸滚轮 =
   整组滑动（对应单图模式的滚轮切媒体），缩放需 `Ctrl+滚轮`（任意状态，
   悬停栏锚缩放）或 `+/-`。未改代码，语义补进快捷键帮助面板。
2. **动画 webp 排除过宽**：原谓词按扩展名把 webp 整体排除，静态 webp 被误伤。
   改法：`compare_eligible` 只按名排除 gif；webp 放行后 `build_compare_pane`
   时以 `webp_animated()` 嗅探（image crate `WebPDecoder::has_animation`，
   **与 imgview 解码分流同一判据**——不引入第二种判定来源）。动画命中落新
   窗格类型 `PaneKind::Unsupported`（与 RawErr 同款占位绘制），滑动窗口把
   动画 webp 带进窗格时同样命中；嗅探打开/解析失败一律按静态处理（不可误拦）。
   坑：`WebPDecoder::new` 要求 `BufRead`，裸流（VirtualFile/File）需套
   `BufReader`（imgview 是 `Cursor<Vec<u8>>` 天然满足，无此坑）。
3. **←/→"还是翻页"**：核实为按设计语义——多帧 raw 会话 = 帧游标，纯静态
   兜底 = 整组滑动（即"翻页"观感）。未改代码，语义补进帮助面板。
4. **快捷键帮助缺对比组**：帮助弹出面板加第四组「对比模式」（琥珀色 =
   主栏同款），列全 Esc/PgUp/PgDn/←→/2~6/缩放/滚轮/拖拽/主栏点击语义。

- 代码落点：`compare_eligible` / `webp_animated` / `PaneKind::Unsupported`
  / `build_compare_pane` 嗅探分流（ui/compare.rs）、panels.rs 帮助第四组 +
  Unsupported 绘制分支；测试 +2（静态/动画嗅探，动画夹具复用
  smoke/img/anim2.webp，缺失即 panic，见 [06 §6.1.1](06_测试运行方式与覆盖矩阵.md)）。
- 教训：**按名不可分的能力差异，入口谓词放行、消费点分流**（window 函数
  无法嗅探就别让谓词假装能）；**"语义没实现"与"语义不可发现"是两类问题**，
  后者修帮助面板而不是改语义。

## 实测修复：滚轮/C 键双失效 + ←/→ 语义去复用

第二轮实测反馈：滚轮（含 Ctrl+滚轮）全失效、C 键多选后按无效；另 ←/→ 语义变更。

1. **滚轮全失效（真 bug）**：滚轮读取以视频区父响应 `resp.hovered()` 为闸，
   但对比各栏 `allocate_rect(click_and_drag)` 是交互子控件——**egui 父控件
   hover 被交互子控件劫走，恒 false**。单图模式图片是纯 Mesh 绘制、无交互
   子控件，同款闸门从未暴露。修复：闸门改 `ui.rect_contains_pointer(video)`
   （矩形含指针，不受子控件交互影响）；`resp` 参数降级 `_resp`。
2. **C 键失效（真 bug）**：nav.rs 既有结论「中文输入法下字母键往往只产生
   Text 事件（无 Key 事件）」，M/L 已有 Text 兜底而 **C 漏了**——IME 开启时
   按 C 只产生 Text 事件，`Key::C` 臂永不命中。修复：Text 分支加
   `"c"/"C"` 兜底（无模式门控，与 Key 臂一致，校验在 try_enter_compare）。
   教训：**nav 主键表每加一个字母键，必须同步检查 Text 事件兜底**。
3. **←/→ 语义变更（用户定案）**：纯静态会话不再兜底组滑动（"翻页"观感与
   帧步进心智混淆）——组滑动专属 PgUp/PgDn 与 fit 态滚轮；纯静态会话 ←/→
   不响应。帮助面板与 §16 键表同步。

- 测试：全量 176 项通过（滚轮/C 为 UI 交互路径，单测不可达，冒烟验证）。
- 教训：**父响应 hovered() 在有交互子控件时不可用**（egui hover 劫持）——
  凡"区域级悬停"判定一律用矩形含指针，不用父响应 hover。

## 修复：首档缩放跳变（显示公式基准错位）

实测：6 栏 fit 很小，放大一下直接跳到约 5 倍（体感"一下子到 100%"）。

- 根因：**步进函数与显示公式语义错位**。`sync_zoom_step` 把 Some(1.0) 定义为
  fit（步进已是 1.25/0.8 平滑步进），但绘制/拖拽/滚轮三处 disp 用
  `native * zoom`（100% 基准）——6 栏 fit≈0.2 时首档 Some(1.25) =
  原生大小 ×1.25 ≈ 6.25 倍 fit，正是 5 倍跳变。修复：三处统一
  `native * fit * zoom`（fit 基准倍率）。几何纯函数本身正确，是消费侧公式
  写错了基准——**设计文档写对了、单测钉住了纯函数，仍拦不住消费侧偏离**，
  教训：缩放语义这类"倍率基准"应在消费侧也用同一条公式（提取 helper 或
  注释钉死 `disp = native * fit * z`）。

## 修复：未播放态 C 键失效（nav 极简早退分支漏放行）

实测：未开始播放时全选列表按 C 无效，右键菜单有效。

- 根因：nav.rs 的「无播放器且无图片纹理」早退分支（未打开任何媒体时的
  最小快捷键集）**只放行 M 静音**，C 被早退吞掉——"还没播放"≠"没打开
  压缩包"，选中集/压缩包态在此分支下均可用。右键菜单不走 nav 分派，
  所以菜单能进对比而 C 键无效。
- 修复：极简分支补 C（Key + IME Text 两路，Key 臂不加修饰键门控——该分支
  无其它 C 语义，且 Ctrl+A 全选后修饰键快照可能残留（DEVLOG §11），门控
  反而会杀掉紧跟全选的 C）。
- 教训：**nav 每加一个快捷键，必须同步检查两处早退分支**（对比模态分派、
  无播放器极简分支）+ Text 事件兜底——三个放行点缺一即"时好时坏"。

## 追加：↑/↓ 复用为缩放步进

用户提议对齐单图模式心智（图片态上下箭头 = 缩放）：compare_shortcuts 补
↑/↓ 臂，与 +/− 完全同义（zin/zout，1.25 步进，fit 为底，↓ 在 fit 态无事）。
帮助面板与 §16 键表同步。至此对比模态四方向键语义齐全：←/→=帧游标
（多帧 raw）、↑/↓=缩放、PgUp/PgDn=组滑动、Home=回 fit。

## 追加：帮助面板对比组精简为"差异说明"

用户指出对比键位与单图大面积同构（↑↓/+/−/Home/滚轮锚缩放/拖拽全同义），
帮助面板只列差异五条：←/→ 不再翻页（帧游标）、PgUp/PgDn=翻页、2~6 栏数、
点击设主栏、Esc 两层退出；组标题注明"其余键同图片模式"。**帮助文档与
键位表分工**：面板内嵌帮助面向肌肉记忆（只说增量），§16 架构键表保持
全量（面向实现者核对语义）。后续微调：PgUp/PgDn 归位通用组（nav 主键表
本就无模式门控，对比括注"整组滑动"）；C 键独立成行说明（入口条件完整
描述）；右键菜单「对比显示」去掉"（C）"后缀（菜单与快捷键解耦呈现）。

## 追加：回车全屏失效修复 + 组滑动就绪闸门与双向预取

两处实测反馈：

1. **回车全屏失效**：对比模态"独立键表全权接管"（nav.rs 提前 return），
   主键表的 Enter 臂永远收不到事件——对比键表漏补通用键。修法：
   compare_shortcuts 补 Enter 臂（set_fullscreen 切换）。**教训：模态键表
   接管 = 必须盘点通用键全集**（此前 Esc 已补位，回车是第二例）。

2. **组滑动体验**：PgDn 先换屏、新末栏显示"等待落地"——非流式包新入栏
   条目文件未落地/未解码。三层改造：
   - **双向预取**（compare_after_change）：窗口前/后各 pane_n 个合格静态图
     （原实现只有流式包前进方向），候选键全部进 `shown_multi` 逐出保护集
     （6+2N 语义；此前预取纹理会被 LRU 正常逐出，滑动时可能白预取）；
   - **非流式落地补发**（compare_tick）：候选文件落地（source_ready）后
     发起解码，预取纹理在滑动前就绪；
   - **就绪闸门**（compare_slide）：Incoming 是静态图且未就绪时挂起整组
     滑动（pending_slide = 方向+key+idx），tick 轮询就绪后自动滑；值得等
     的判据 = 流式（解码随时在途）/ 非流式（解码在途 ∨ 解压会话 pending
     表含该条）；就绪路径消失（解码失败、会话不覆盖）则放弃挂起立即滑动
     （否则会卡死翻页），栏内占位文案兜底。挂起不排队，重复按键覆盖。

用户疑问澄清：原实现 LRU 保护集只有窗口 6 键，预取无保护、且只有前进
方向——"6+1"从不存在，本次改为 6+2N 且受保护。180 项测试通过。

## 追加：通用键/图片键全量补位 + 预取深度收敛 + 主栏 100%

用户要求通用类与图片类快捷键在对比模式全量实现，不确定语义的四处
AskUserQuestion 定案：

- **B 回到锚点** = 主栏吸附：滑动域含锚点条目时整组滑窗吸附（锚点靠
  窗口中部）并设为主栏，不在域内提示；zoom/center/cursor 保持。
  `compare_focus_jump` 实现（domain 上重开连续窗口，非 slide_window）；
- **0 键** = 主栏 100%：共享 zoom 是相对各栏 fit 的倍率，无单一 100%
  语义——按方案 A 主栏锚定换算 zoom = 1/主栏 fit 缩放比。
  compare_view 每帧记录主栏 `(fit 显示尺寸, 原生尺寸)`（Image 与 Raw
  分支都记录，raw 栏可为主栏）进 `master_fit`；
- **双击某栏** = 整组回适应（单图双击的"↔100%"半边由 0 键承担）；
- **N 键** = 通用语义照搬：ask_next_archive(false)。**配套守卫**：切换
  压缩包时对比会话随旧包清除（apply_open 旧包状态清理点补
  compare.take + clear_shown_multi + rawdec.retain——栏键含 archive_id，
  旧包键对新包全部失效）。

**预取深度收敛**：用户指出"每次翻页只滑一张，栏数+1 就够"——采纳，
pane_n/方向 → 1 张/方向（6+2）。决策依据：就绪闸门已保证不白等，深度
只影响连续快翻前几下是否零等待，而稳态翻页间隔（秒级）远大于解码耗时
（百毫秒级），深度 N 白驻 ~100MB 纹理。帮助面板与 §16 键表同步。

**选中集生命周期**（用户提议采纳）：选中集是"待处理意图"，两类消费
入口处理即清——对比模式 `try_enter_compare` **进入成功即清**（选择已
转化为会话窗口；失败路径早退不清便于重试，截断提示先存 `sel_count`
再清避免引用空集）；编码 `start_encode` **任务真正启动才清**（确认窗
取消路径保留选择，用户可微调后重开窗）。两处语义不同源"模态接管"与
"批次提交"的差异。

**"预取下一组中"提示闪现**（用户实测反馈）：滑动体感无等待但提示一直在
——根因是提示在**闸门挂起瞬间**就上屏：按 PgDn → Incoming 未就绪 → 挂起
+ set_notice → 下一两帧解码完成自动滑。滑动百毫秒级完成，但提示条驻留数
秒，连翻时看似"一直在提示"。修复：提示延迟化——挂起静默，等待超 300ms
才提示（`pending_slide` 从三元组扩为 (dir, key, idx, since, noticed)）。
教训：**反馈提示的时机应锚定"用户真实感知到的等待"而非状态转换**——
状态转换 ≠ 用户需要被告知。

**控制栏按钮劫持对比**（用户实测反馈，两轮）：底部控制栏 `<` `>` 与
未播放态 ▶ 都汇入 `act.step` → `play_adjacent` → `play()` 顶部清对比 =
点击按钮意外退出对比模式/视图跳变。

- 第一轮：动作消费点加对比感知——`act.step` 在对比模式改走
  `compare_slide`（与 PgUp/PgDn 同语义）；`act.toggle` 加门控（空格在
  对比模态被独立键表全权接管后 `return`，主键表 Space 臂无落点 = 完全
  不响应；而按钮 toggle_pause 会翻转缓存暂停态致 ▶/|| 图标假切换）；
- 第二轮：未播放态中键 ▶「从第一项开始播放」也复用 `act.step = 1`，
  被第一轮的重映射捎带成了组滑动（视图跳变）。修法：动作分立——新增
  `act.start`，中键改发 `act.start`（消费点 `compare.is_none()` 门控），
  `<` `>` 独占 `act.step`。教训：**动作复用一个字段时，对某入口的
  重映射会波及所有共用该字段的入口**——分立语义或先盘点全部写入点。

## 追加：像素探针（Alt+左键）+ orig-lru LRU 化 + 对比 full 重采样使能

**像素探针（用户需求）**：对比调参需要读具体像素值确认差异。Alt+左键取点，
画十字标记 + 悬浮信息（原图像素坐标 x/y + RGB + YUV(BT.601)），单图与对比
两视图同款。实现要点：

- **归一化坐标防漂移**：探针点按归一化图像坐标（uv 0..1）存储，显示时按
  各栏原图尺寸换算——base/full 纹理切换、缩放、平移都不漂移；存屏幕/纹理
  像素坐标则任何档位翻转都会错位；
- **原图取样**：像素值从 orig-lru 取样（`ImageService::original_pixel`），
  非显示纹理插值——否则读数随放大档位变化，探针失去意义。**orig-lru 单槽
  改 LRU**：原单槽在 full 升级时被取走清空（单槽时代"用完即弃"），对比
  多栏每栏都可能被探针点名 → LRU 化且 full 就绪/失败**不再清空**（条目按
  LRU 自然逐出）。容量语义演进两阶段：① 自适应 = tex-lru 保护集同语义
  "当前栏数 + 2"（单图 3、对比 n 栏 n+2）——初版固定 cap=6，用户复查提出
  随分栏数变化 + 与 tex-lru 统一管理，实测确认两缓存本无重复内容；
  ② **改字节预算制**（per-file 亮度需求扩容，config `[image]
  image_orig_cache_mb` 默认 512，钳 64~4096）：原"只收 native×ppp ≤
  max_dim 预放大资格小图"的尺寸限制解除——为扩大像素探针覆盖范围 +
  `[ ]` 亮度毫秒级重建免重解码，原图统一驻留；单张准入 = 预算/2（超准入
  巨图退回旧行为），张数 cap（栏数+2）与字节预算**双护栏**逐出最旧、跳过
  当前显示与对比保护集（全保护时暂时超支，随显示切换自然可逐出）；
  （命名清单：tex-lru = GPU 纹理缓存 LRU / orig-lru = CPU 原图缓存 LRU /
  full-slot = GPU full 高清单槽，见架构 13.4 缓存清单表）
  **补遗（2026-11-19）**：热重载同步漏接线——`set_orig_budget` 方法写好了
  （doc 注释即"config 热重载同步"）但 reload_config 只调了 `set_cap`，
  dead_code 告警暴露；补上调用，预算收缩与 set_cap 同语义（下次推入时
  逐出生效，已驻留内容不主动丢弃）；
- **跨栏同步判定**：点击栏与目标栏**同类型且分辨率相同**才同步显示——
  同类型同分辨率下同一 uv 即同一像素坐标；类型不同（图像↔raw 读数语义
  不同）或分辨率不同则同一 uv 指向不同像素，强行同步是误导，只在点击栏
  显示。图像↔图像按 orig-lru 原图尺寸比对，raw↔raw 按 RawFrameInfo 尺寸
  比对；
- **raw 栏不参与**：raw 软解帧即解即传纹理、无 CPU 像素驻留，探针无取样
  来源——是取样语义（"原图级真实值"）的固有限制而非缺陷
  （**后续已解除**：见下节「追加：raw 栏像素探针」，改走 rawdec 按需读源）；
- **原图未保留兜底**：动图 / 超预放大资格的超大图 / 已逐出 → 显示"原图
  未保留"；
- **显示**：文字全透明背景，按取样像素亮度自动黑/白字（≥128 黑字否则白字）
  + 反色 1px 阴影兜底（任何底色可读）；信息框点击点右下偏移、超界折回；
- **清除时机**：切图（key 变化）、进入对比、对比窗口整组滑动/改栏数——栏
  内容换血后旧探针坐标指向别的图，必须清；
- 代码落点：panels.rs / compare.rs / ui/mod.rs（探针状态与绘制）、
  imgview.rs（original_pixel + orig-lru LRU 化）。

**对比 full 重采样使能（`image_compare_full_resample_enable`，默认关）**：
用户实测对比模式深放大 full 档"无感"——base 档纹理（×ppp 预放大）在同屏
对比下已够用；full 档主栏与 base 档副栏锐度不一致反而干扰判断，且主栏点击
切换逐次触发 full 解码是纯开销。新增 `[image]
image_compare_full_resample_enable`（默认 false）控制对比下主栏深放大是否
触发 full 解码与选画 full 纹理；单图模式不受此键影响（恒允许升级）。命名
定稿过程：初名 `image_compare_full` 被用户指出过于简略难懂（"full 高清
升级"读不出行为），改为"full 重采样使能"信息命名。教训：**模式观感目标
不同，共享判据要留模式级覆盖**——full 升级为单图"看细节"设计，对比模式
目标是"看差异"，默认关是语义正确档位而非功能缺失。

## 追加：raw 栏像素探针（按格式读存储原值，直读磁盘）

**需求与定位**：用户要求 raw 栏也支持像素探针，按内建格式分流显示——NV12
显示 YUV 值、GRAY 显示亮度值、BAYER 显示当前 2×2 块原值。**不做帧级转换
缓存**（用户裁定）：raw 无解码过程，所需数据仅几个字节，切换/点击时重新
读磁盘即可，缓存反而引入失效管理复杂度。

实现要点：

- **读数语义 = 文件存储原值**：未做 bit_shift 位移、未插值成 RGB——显示
  画面是转换产物，探针要的是传感器/编码前的原始采样值。位深有效值 = 
  16 − bit_shift（gray16le 12bit 数据显示 bits=12）；
- **按格式取数**（rawdec::probe_raw_pixel，uv → 像素坐标 clamp 后按字节
  偏移直读）：gray 1B / gray16le 2B / nv12 3B（Y + 按 (x/2,y/2) 取共享
  U/V）/ bayer 两行各 4B（采样点对齐 2×2 块）。bayer_auto16le 伪格式先
  seek 首帧 resolve_auto_bayer 探测排列再取值；
- **帧寻址复用**：从 decode_raw_frame 抽出 FrameReader 枚举（VFS 流 / 
  本地文件两态）+ open_frame_reader 共用，第 k 帧 = k×frame_bytes seek，
  与软解主路径同一套寻址逻辑不引入第二套体系；
- **异步状态机**：服务 tx/rx 从 `Sender<RawFrameDone>` 改为
  `Sender<RawMsg>`（Frame / Probe 两分支，poll 分发）；新增 ProbeEntry
  { idx, uv, res } 状态表 + request_probe（同 key 同帧同点幂等不重发，
  spawn "rawprobe" 线程）+ probe() 查询；迟到结果按 (idx, uv) 匹配才收，
  不匹配丢弃（用户已换帧/换点）；在途显示"读取中…"，失败显示"探针失败：
  {e}"。retain() 同步清理 probes 表；
- **跨栏同步分流**：raw↔raw 按 RawFrameInfo 尺寸比对（与图像↔图像按
  orig-lru 原图尺寸比对同构）；图像与 raw 互不同步（读数语义不同，同一
  uv 的像素含义不同——raw 是存储采样值、图像是 RGB）；
- **格式覆盖对齐**：探针格式分派（probe_raw_pixel）与软解判定/分派
  （soft_decodable / decode_raw_frame）逐条对应（探针集 = 软解集）——
  软解不支持进不了栏、无需覆盖；**约束写入两处函数 doc 注释与架构 16.9
  不变量：rawdec 新增软解格式时必须同步增加探针格式显示分支**；
- **展示**：Nv12 → `x=… y=…  YUV(y,u,v) (4:2:0)`；Gray →
  `x=… y=…  GRAY(v, bits bit)`；Bayer → 两行显示排列名 + 位深 + 2×2 块
  四原值；亮度折算按有效位深（非固定 8bit）选黑/白字；
- 单测 `probe_raw_pixel_按格式取存储原值`：nv12 两帧验证帧寻址、bayer
  rggb bit_shift=4 验证采样点对齐与原值、gray16le 验证 16bit 读数。

教训：**"没有解码"≠"没有成本"**——raw 栏读取仍有 VFS 流 + 逐像素转换
成本，此前一版据此拒绝探针是过度保守；正确的颗粒度是按"点击直读几个
字节"重新核算成本（读 3~8 字节可忽略），而不是按"重新软解整帧"拒绝。

**探针"原图未保留"僵尸态（shoot dump 实测踩中）**：同一批 dump 图只有
最早浏览的 shoot 图探针失效，其余正常。根因是 **orig-lru 与 tex-lru 生命
周期不对称**：tex-lru 的 frame() 每次显示都提队首，orig-lru 只在解码就绪
时插入、查看不刷新——来回浏览后顺序分叉，某图纹理因"最近看过"留在
tex-lru，native 却因解码较早被挤出；切回时 `has()` 命中纹理（查
tex-lru）不发重解码请求，Ready 永不再来 → native 永不回归 → 该图探针
永久"原图未保留"。修复：frame_ex 提队首时同步把 natives 同 key 条目提到
队首——**"纹理在 ⇔ 原图在"成为不变量**（orig-lru 双护栏：张数 cap =
纹理保护集同语义"栏数+2" 恒 ≥ tex-lru 驻留数 + 字节预算
`image_orig_cache_mb`，单图与对比都覆盖；容量语义演进见前文「原图取样」）。教训：**两个伴随
的 LRU 必须统一 touch 时机**——只在一侧做"显示即提队首"，另一侧靠插入
序，容量再匹配也迟早分叉；连带探针显示改三行紧凑格式
`[x, y]` / `R() G() B()` / `Y() U() V()`（raw 栏同款风格）。

**跨栏探针同值 bug（4 栏实测踩中）**：某栏放置探针后 4 栏显示同一份
数值。根因：paint_probe 内部读数用 `probe.key`（发起栏），而跨栏同步
绘制时每栏都拿同一个 probe 对象调用——各栏都读了发起栏的像素。修复：
paint_probe 增加 `pane_key` 参数（当前绘制栏 key），发起栏 probe 只提供
同步 uv 不提供读数来源，各栏按自身 key 各取各的原图/raw 像素。教训：
**共享几何 + 独立读数**是跨栏同步的两种数据，必须用两个参数分开传递，
不能让一个结构体同时携带两者。
