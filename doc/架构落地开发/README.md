## 维护约定（强制）

**代码需求变更、新增功能、BUG 修复，都必须同步更新本目录文档**，不得只改代码。
本目录是 BUG 修复与代码实现细节的**唯一**记录处：

- **BUG 修复 / 踩坑 / 排查过程**：在已存在的对应专题文档中追加
  （现象 → 根因 → 修复 → 教训，带回归测试说明）；专题定位不变；
- **全新专项**（新子系统 / 大型需求变更自成一线）：新增一个专题文档
  （编号顺延，如 `12_新专题.md`），并回填本 README 目录表与对应架构章节列；
- **新功能 / 需求变更**：动机、实现细节、测试都落本目录对应专题；
- **代码实现细节**（模块内部行为、调试方法、性能实测数据）也落本目录；
- **本目录不写宏观机制设计**：设计 / 决策 / 不变量归
  [架构设计](../架构设计/README.md)——机制变化时同步那边的设计描述，
  本文只留一行指引。

一句话：本目录回答"具体怎么做的、坑在哪、怎么排查"；"为什么这么设计、
边界在哪、不变量是什么"一律在架构设计目录。
