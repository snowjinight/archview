# §16 图片高清档密度重构专项

> 对应架构设计：[ARCHITECTURE §13.4](../架构设计/13_渲染架构迁移.md)（两档纹理体系/zoom 语义/高清升级）、[§6.3](../架构设计/06_图片预览模块.md)。
> 本文记需求变更动机、方案取舍、实现细节与性能实测；机制与不变量见架构章节。

## 1. 需求动机

用户实测：2560×1440 图、150% DPI 屏，在 badge 304% 处对比 Windows 自带看图
软件同倍率，「FULL 高清放大与纯双线性放大无任何区别，看不到 Lanczos 特征」。

排查结论（链路逐环验证过，触发→二次解码→Lanczos→锐化→GPU 上传→换画日志
全部正常）：**full 纹理密度不足**。

- badge 是「基础纹理相对倍率」（badge = zoom×ppp×100），与 Windows 看图的
  「原图相对倍率」差 ×ppp（150% 屏 badge 304% = 原图 456%）——两把尺子混用
  是观感困惑的一半根因；
- ×2 密度的 full 纹理在 badge 300%+ 区间被 GPU 末级双线性主导：full 纹素物理
  尺寸 = ppp×badge/F（F=ppp×2 时 304% 处采样比 0.76×，紧贴欠采样），Lanczos
  预放大的边缘增益被末级缩放抹平。

用户明确需求：**2K 图在 300%~400% 放大区间清晰锐利即可，不做深放大**；
同时约束 1080P/720P 大众分辨率、原生 4K 图与相机 7000P 级图片质量不得劣化。

## 2. 方案（用户确认定案）

| 项 | 旧 | 新 |
|---|---|---|
| full 倍率 | ppp×2 | **ppp×3**（150% 屏 = ×4.5，badge 450% 处 full 纹素 1:1 甜点） |
| 尺寸封顶 | `FULL_MAX_DIM` 8192 | **预算制**：最长边 12288 + 像素预算 100MP（超预算 sqrt 等比缩回） |
| 原图来源 | full 升级重读源二次解码 | **base worker 顺手保留原图单槽缓存**，full 命中免二次解码 |
| 重采样 | image crate 单线程 Lanczos | **fast_image_resize SIMD**（SSE4/AVX2，同一 Lanczos3 核） |
| 锐化 | 默认开、放大后 33MP 级执行 | 放大前原图级执行；**观感增强链**：双边降噪 → unsharp（amount/σ/降噪三参数可调） |

曾被否决的思路：按当前分辨率「顶满 8192」一次性放大到位——倍率与屏幕解耦后
无法保证 1:1 甜点，且小图全尺寸放大浪费显存；×3 密度 + 预算制在甜点语义与
显存上限间取得平衡（用户已确认）。

## 3. 性能实测（2560×1440 PNG，full 一次）

旧链路 full 解码 1330ms（LOG.txt），拆解：

| 成本项 | 旧 | 新 |
|---|---|---|
| PNG 二次解码（full 重读源） | ~300ms | 0（原图单槽缓存命中） |
| Lanczos 33MP | ~600ms | ~80ms（fast_image_resize SIMD） |
| 33MP 高斯 unsharp（锐化默认开） | ~400ms | 0（默认关；开启时原图级 ~15ms） |

新链路（缓存命中 + 锐化关）合计 **~100ms 级**；即使缓存未命中（切图后直接
深放大）回退重解，SIMD + 锐化关也在 ~200ms 级。

质量约束核对：4K 图（3840×2160×4.5=12288×6912≈85MP ≤100MP 不触预算）、
7000P 相机图（7000×4667×4.5 触 12288 封顶 → 12288×8190≈100.7MP → sqrt 缩回
~99.7MP）——高分辨率图自动被封顶钳住，不爆显存不劣化；1080P/720P 小图
×4.5 全程在预算内直出。

## 4. 实现细节（src/imgview.rs）

- 常量：`FULL_MAX_DIM = 12288`、`FULL_MAX_PIXELS = 100_000_000`；基础档病态
  兜底 `MAX_TEX_DIM = 8192` 不变（`upscale(img, factor, cap)` 的 cap 参数区分）。
- `decode_image`/`decode_any`/`finish_static` 返回值改
  `(Decoded, Option<DynamicImage>)` 元组：静态基础档按资格判据
  `native×factor ≤ max_dim`（与预放大判据恒等）保留原图；动图分支恒 `None`。
- `ImageService` 新增 `native: Option<(ImgKey, DynamicImage)>` 单槽：poll()
  Ready 时写入，FullReady/FullFailed 匹配 key 后释放；`request_full` 命中走
  `build_full`（免读源），未命中回退 decode 路径。
- `upscale` 预算二次封顶：12288 封顶后若 `nw×nh > 100MP`，按
  `sqrt(预算/实际)` 等比缩回。**取整必须 floor**：round 会使整数乘积反超预算
  （12288×9830≈120.8MP → sqrt 缩回后 round 出 11181×8944≈100.003MP 仍超，
  单测 `resample_病态图8192兜底` 捕获）；`floor(a)·floor(b) ≤ a·b = 预算` 恒成立。
- `fir_resize`：`into_rgba8` 零拷贝进 `fir::images::Image`，Lanczos3 卷积核
  直出 RGBA8；尺寸/缓冲自洽违例 expect panic 由 worker `catch_unwind` 兜成
  Failed（与既有回退链一致）。
- `finish_static` 锐化移到 resample 前：`if full && sharpen.on { sharpen_full(img, sharpen) }`
  ——原图分辨率执行降噪+unsharp（2K ~50ms），先锐后插。
- 消息链：`ImgMsg::Ready` 新增 `native` 字段随解码结果回传 UI 线程。
- Cargo.toml：`fast_image_resize = "5"`（锁 v5.5.0，默认 SIMD 特性）。

- `ui/mod.rs` 启动回显日志改为 `图片高清升级: 阈值×N 锐化 开(amount 0.60

## 5.1 锐化参数化与降噪（用户实测后追加）

用户 244% 档实测：锐化开 = 边缘明显更脆但噪点上升 → 三点结论：

1. **默认改回开**（首轮方案默认关是基于"Lanczos 增益边际"的预判，实测
   观感增益明显，用户确认默认开——预判让位于实测）；
2. **强度参数化**：`SharpenCfg { on, amount, sigma, denoise }` 结构贯穿
   decode 链（decode_image → decode_any → finish_static → build_full →
   sharpen_full），基础档传 `SharpenCfg::OFF`；σ 调大只增强中大尺度边缘
   （σ 级以下像素噪点被模糊项抹掉、差值趋零），天然抗噪点放大；
3. **前置降噪可行且对症**：手写 3×3 双边滤波（保边降噪）插在 unsharp 之前
   ——空间权重固定 3×3 高斯 σs=1.0，颜色权重按 Rec.601 亮度差的指数衰减
   （σc=25/255）：平坦区噪点被邻域加权均值压掉，强边缘亮度差大权重趋零
   不糊边；中心权重恒 1.0 无除零；O(n·9) 纯 Rust，2K 图 ~30ms 被后台
   Lanczos 主耗时掩盖。三通道共用同一权重保持色彩不偏。

**踩坑（日志快路径缺标记）**：用户反馈"日志里没有锐化的相关打印"——根因
是锐化标记只接在完整解码路径（decode_image 完成日志），而用户命中了**原图
缓存快路径**（request_full → build_full，"高清解码复用原图缓存"日志），
该路径从未打过标记。修复：`SharpenCfg::tag()` 统一产出
" 降噪+锐化"/" 锐化"/空 标记，快路径与解码路径两处日志都接上；启动回显
同步带出 amount/σ/降噪。教训：**日志标记挂在"主路径"时必须盘点所有等价
旁路**，缓存/快路径是最常见的漏网点。

**追加：降噪强度参数化（涂抹感反馈）**：σc 首版硬编码 25，用户实测"噪点
没了但人脸涂抹感重"——皮肤渐变与毛孔属弱纹理，亮度差 <25 的邻点全部参与
平均，被过度抹平。两个动作：① σc 参数化为 `image_full_denoise_strength`
（0~100 亮度级）；② 默认下调 25→15（首版默认即用户抱怨值，参数化后默认
也应落在温和档）。调法：涂抹感重 → 8~15；噪点残留 → 25~50。教训：**"保边"
不等于"保弱纹理"**——双边滤波的边缘判据（亮度差）分不出"强边缘"与"皮肤
渐变+毛孔"这类弱结构，后者的亮度差同样小、照样被平均，涂抹感是双边滤波
的固有边界而非 bug，只能靠容忍度参数换档。

## 5.2 降噪算法切换：导向滤波加入（锯齿反馈）

**现象**：用户用双边默认参数开降噪后，头发边缘出现阶梯状锯齿。归因链：
双边把斜边缘的抗锯齿过渡像素（与两侧亮度差 <σc）吸向邻域均值 → 软渐变
变硬边 → unsharp 再压陡 → ×4.5 Lanczos 放大把硬边显形（GPU 插值不产生
锯齿，锯齿在原图级已埋下，放大只是可见化）。

**库调研**（为什么不手搓也没得选）：轻量纯 Rust 生态无成熟双边/导向滤波
库——scirs2-vision（巨型 monorepo 早期版本）、oximedia-image（0.1.x 影视
定位重依赖）、opencv 绑定（C++ 依赖 + 几十 MB DLL，单 exe 工具不可行）；
imageproc/image crate 均无此二滤波。对比 fast_image_resize（resize 有成熟
库）属特例。结论：教科书级线性算法手搓 ~100 行，无浮点陷阱。

**实现**（`imgview::guided_denoise` + `box_filter`）：He et al. 2010
self-guided 灰度版——引导图 = 自身亮度 I，`q = box(a)·I + box(b)`，
a = cov/(cov+ε)、b = (1−a)·mean_I。要点：
- **ε 与双边 σc 的量纲换算**：亮度差容忍 D 级 ↔ 方差容忍 D²，故
  ε = strength²，两算法 strength 同值即可公平对比（用户 A/B 核心前提）；
- **box 滑窗两段式**（水平行内滑窗 + 垂直列和增量），O(1)/px 与半径无关、
  全程无 exp（双边每像素 9 次 exp 是其性能大头），2K 图 ~40ms 与双边 3×3
  同量级；朴素参考实现钉正确性（可分离两段式 = 2D box）；
- **输出只取亮度校正量 Δ = q − I 加回 RGB**（色度比例保留，与双边"RGB
  共用亮度权重"同效）；中间缓冲原地复用（b 写进 mean_I、a/b 串行 drop），
  峰值 ~4 个 f32 亮度缓冲（2K ~60MB、7000P ~520MB 后台瞬时）；
- **算法切换**：`image_full_denoise_algo`（"bilateral"/"guided"，非法值
  WARN 回退双边不静默），参数按算法名前缀区分
  （`image_full_bilateral_strength` ← 旧 `image_full_denoise_strength` 改名、
  `image_full_guided_strength`/`image_full_guided_radius`），组装收敛到
  `SharpenCfg::from_ui`（panels 两处调用点）；日志标记带算法名
  （" 降噪[双边]+锐化"/" 降噪[导向]+锐化"），A/B 看日志即分辨链路；
- **旧键改名不做 serde alias**：alias 与回写补全新键并存时旧键+新键同时
  出现会触发 serde duplicate field 错误，直接改名靠回写补全。

**测试期望修订**：导向滤波对强边允许 ~几个百分点过渡（box(a)/box(b) 二次
平滑，区别于双边的颜色权重压零硬保留）——首版"强边不动 ±2"断言失败，
修正为"衰减 ≤8 级 / 原差 120"（保边 ≠ 边缘零变化，两算法的"保留"语义
本身有差异）。187 项测试全过（新增 box 参考、压噪/保边、解析回退、分发
真实性四测）。

**对比结论的预期收敛**：导向强在渐进弱纹理/过渡带（结构方差判据），双边
强在孤立强噪点（点到点差压零）；低频 JPEG 块噪两家都不行。用户 A/B 后
删掉输的一家，长期只留一个（切换是临时复杂度，最终收敛）。

**A/B 实测定论（两算法都留）**：用户同图对比——双边（10/0.45/σ1.5）锯齿
弱于旧参数、眼部更清晰，但头发投影分层（暗部渐变 banding）；导向（10/r2）
锯齿感更弱但眼部清晰度略低，整体略优。**两算法差异是判据本质（点到点差
vs 窗口方差）而非参数能弥合，各有适用图源，切换保留**——推翻 5.2 初版
"对比后删一家"的预期，两套参数长期共存（切换语义由"临时评估"转为"正式
能力"）。分层归因修正（用户指出 σ 不该背锅）：分层是**双边 3×3 小窗口
平滑弱 + 大 σ 锐化拉开暗部量化台阶**的组合问题，导向 r≥2 平滑强无此
现象——换算法即可解，σ 保持 1.5 不动。

**光晕共同解：过冲钳制**：两算法在头发边缘均现光晕——unsharp 固有过冲
（强边 diff 可达 ±60，×amount 后光晕 20~40 级，×4.5 放大成亮线/暗线），
与降噪算法无关。解法 = 钳差值不钳输出：`diff.clamp(±20)` 后再乘 amount
（经典 smart-sharpen 做法）——细纹理 diff ±5~15 全额保留锐度不变，强边
过冲封顶 ±20×amount ≈ ±12 级（保留少量锐感，全灭=强边不锐）。固定内置
±20 不参数化（用户偏好简单；有需求再加）。

**默认值定版（用户实测最优组合落默认）**：amount 0.6→0.45、sigma 保持
1.5（分层归因见上——双边小窗口组合问题，换默认导向即解，σ 不动）、
双边/guided strength 15→10（用户 A/B 同值实验档）、**algo 默认
bilateral→guided**（用户实测导向锯齿最弱、分层无，定为默认；parse 非法
值回退目标与 WARN 文案联动改导向）。教训：**调参实验的最优组合应回写
默认值**，否则"默认即用户抱怨值"的坑（§5.1）反复重演；归因错给全局
参数（σ）而回退它，用户会立刻指出——分层/锯齿类复合症状先按"换算法"
与"调参数"两条路分别归因。

**终版微调 + 场景参数分组（用户深放大实测二轮）**：用户实测导向
r=1/strength 5/amount 0.5 观感更好 → 默认值二轮回写（0.45→0.5、
guided 10→5、radius 2→1）。机理解释成立并被用户认可：**链路是三个频带
接力**（降噪管最细高频、unsharp 管中高频边缘、Lanczos 只摊开可见化），
r=1 刚好覆盖 1~2px 噪点自相关尺度且方差估计最局部（大窗口把发丝间隙/
毛孔方差稀释 → 误判平坦 → 涂抹），strength 5（ε=25 = std ~5 级门限）
刚好卡在噪点幅度带；降噪留的高频多，amount 可开更猛。据此机理推广出
场景参数分组（写入 config.toml 模板 amount 注释与架构 13.4）：暗光
高ISO（15~25/r1~2/0.4~0.45）、风景白天低ISO（3 或降噪关/1/0.5——细密
纹理是真信号别压）、漫画线稿截图（降噪关/0.3~0.4——无噪可压，导向会
吞平色区渐变）、JPEG 重压缩（8~10/r2/0.3~0.35——块噪低频两家治不了，
压 amount 别放大它）、胶片颗粒（20~30/r2/0.3~0.4）。

## 5.3 白边抑制：shoot 多尺度方差替代过冲钳制（用户实测三轮）

**过冲钳制退役**：±20 钳差值实测无感（用户反馈"感觉其实没啥用"）——
对称钳制把强边正向增益与暗侧压暗一起削，强边锐感损失换来的光晕缓解
不明显。删除 HALO_CLAMP。

**shoot 白边抑制**（用户给相机 ISP 库 shoot.c 片段指路）：逐点 3×3/5×5/
7×7 多尺度亮度方差算 shoot 值——`shoot = ¼·max(0, var7−var3) +
½·max(0, var7−var5)`（get_shoot_value mode 0 的浮点化）。机理：
- 孤立强边**周围**：7×7 窗口包住强边而局部 3×3 平坦 → 方差差大 → shoot 大
  ——恰好是 unsharp halo（σ 级外扩 2~4px）出没的位置；
- 细纹理/噪点：各尺度方差相近 → shoot≈0 → 不抑制，锐度全额保留；
- 强边正中心：var3≈var7（两窗都半跨边缘）→ 抑制温和，边缘仍提亮不"肉"。

**ratio 只压正向**：`d>0` 时增强乘 `ratio = soft/(soft+√shoot)`（shoot 越
大 ratio 越小，∈(0,1]），`d<0`（暗侧压暗/暗晕）不抑制——白边只出现在
亮侧。soft 单位"亮度级"（√shoot 的量纲），默认 8：8/(8+11.5)≈0.4（128 级
强边邻域），8/(8+2.8)≈0.74（弱边），细纹理 ≈1。

**实现**（imgview.rs `shoot_ratios`）：复用既有 `box_filter`（边界 clamp
滑窗均值，与朴素窗口全量比对测试钉死）算 E[x]/E[x²] → var = E[x²]−E[x]²，
三尺度 O(n)、无 exp；Rec.601 亮度单通道算方差、RGB 三通道共用同一 ratio。
`soft<=0` 跳过方差计算直接全 1（关闭档零开销）。

**配置**：新增 `image_full_shoot_soft`（亮度级 0~100，默认 8，0 = 关），
amount 注释同步去掉 ±20 钳制描述；架构 13.4 / 07 [ui] 键表同步。

**测试**：`sharpen_full_过冲钳制` → `sharpen_full_白边抑制`——断言从
"两侧增量都 ≤13"（对称钳）改为 **亮侧提亮 < 暗侧压暗**（非对称性即抑制
生效的证据）+ `shoot_soft=0` 恢复两侧对称（±1 取整容差）+ 细纹理凸起
正向增强全额保留（shoot≈0 不误伤）。

### 5.3.1 shoot 性能收敛：整数组合 + 负斜率直线（用户指路定案）

初版 sqrt 公式 2K 实测 ~91-95ms，用户纠偏"陷入过度优化循环"并给出三个
收敛方向，全部采纳：

1. **现成库调研（结论：没有）**：Rust 生态无滑动窗口方差 SIMD 库——
   fast_image_resize 只做重采样、imageproc 无此项。滑动方差本质 = 两次
   box 均值（E[x] 与 E[x²]），积分图 O(1) 查表就是该计算的标准 SIMD 友好
   形态（纯查表 24 load/px 实测仅 9ms），无需引库；
2. **ratio 换负斜率直线**：shoot.c mode 0 本来就把 shoot_v CLIP 到 0..255，
   直接 `ratio = 1 − shoot_v/soft` 线性衰减——零 sqrt 零除法（inv_soft 预
   算乘）。**关键纠错**：shoot.c 的 CLIP 作用在**跨尺度方差差**上（uint16
   方差本身可达数千不钳），若先把方差钳到 255 强边方差差会被抹平、机制
   整个失效；soft 语义相应从"sqrt 域软阈值"改为**全抑制截断点**（ratio 降
   为 0 的 shoot_v 值，默认 255 = 全程直线，0 = 关）；
3. **低精度整数化**：窗口和先收 u32（sum ≤ 255×49、sumsq ≤ 65025×49）再转
   f32（u64→f32 无 AVX-512 时是多周期软序列）；方差数学保持 f32（mean² 有
   小数），shoot 组合全程 i32 整数（对齐 shoot.c uint16 语义）——shoot 检
   测不吃精度，整数化零观感损失。

**结构谜团与解法**：分段计时发现合成循环 77ms vs 等价手写循环 30ms，sqrt
+除法只占 ~6ms 根本不是瓶颈。定位：逐像素 `if 内部区/边框` 分支 + 循环内
closure 结构阻碍优化。解法 = **内部区无分支直跑**（3..h−3 双循环 + 
`#[inline(always)]` 自由函数 `window_var`/`shoot_ratio`，热循环零分叉）+
**边框窄带四条带各自直跑**（免全图 3.7M 次无效分支判断）。改造后 2K 实测
~60-68ms（95ms → 65ms 级），与手写基准（方差数学 25ms + ratio 写回）的
剩余差距属测量噪声区间，不再追——链路里 blur σ1（~124ms）本就是更大头。
教训：**性能谜团先查"循环结构"（分支/closure/边界处理混进热循环），再查
数学运算**；合成基准（纯查表/纯数学分档计时）是定位的钥匙。

**配置**：`image_full_shoot_soft` 语义改全抑制截断点（1~255，默认 255），
档位 64=狠 / 128=中强边全灭 / 255=默认缓；随后键名按用户意见改为
`image_full_sharpen_white_edge_soft`（"soft"是旧 sqrt 软阈值遗留、名不副
实；改名不做 serde alias，旧键残留靠回写补全清理，同 §5.2 改名先例）；
soft=0 时连方差计算都跳过（sharpen_full 里 `if soft > 0.0` 才进
shoot_ratios，关闭档零开销）；架构 13.4 / 07 [ui] 键表同步。

### 5.3.2 白边抑制折点曲线：单斜率直线 → 用户可调曲线查表（用户实测三轮）

**直线被弃用**：用户实测单斜率直线（ratio = 1 − shoot_v/soft 全局斜率）
效果不好——低 shoot_v 段衰减太快，弱边/细纹理被压太多。新需求：shoot_v
小 ratio≈1，到可配置拐点（~200）后渐进压制，255 降为 0。

**方案讨论**（用户问"加参数还是加分段表格"）：关键事实是 **shoot_v 只有
256 个可能值**——无论配置侧什么形状（两参数 knee / smoothstep / 折点表），
运行时都收敛为一次预计算的 256 项 ratio 查表（`lut[shoot_v]`，1 load +
1 add，比直线乘法还快），配置形式与性能完全无关，选型只看表达力。折点表
（用户提议 `[[100,0.8],[200,0.6],[240,0.2],[255,0.05]]`）涵盖两参数与
smoothstep 能表达的一切曲线，定为方案。

**实现**（imgview.rs + config.rs）：
- config 键 `image_full_sharpen_white_edge_curve: Vec<(f32, f32)>`（折点
  [shoot_v, ratio] 数组），默认曲线单一来源常量
  `DEFAULT_WHITE_EDGE_CURVE`（[150,1]→[200,0.7]→[240,0.25]→[255,0]）；
- `build_white_edge_lut`：隐含首点 [0,1]（首折点前从 1 渐变到首点 y——
  细纹理轻压不误伤，lut[0] 恒 1 机制保证）、折点间**分段线性插值**、折点
  精确落值、末点后平坦 = 末点 ratio（用户例 [255,0.05] = 极强边保留 5%
  增强不掉锐感）；
- `parse_white_edge_curve`：校验 x ∈ (0,255] 严格递增、y ∈ [0,1]，非法
  回退默认曲线并 WARN（同 DenoiseAlgo 先例）；**空数组 = 关闭**（None，
  连方差计算都跳过，延续 soft=0 零开销语义）；
- `SharpenCfg.shoot_soft: f32` → `white_edge: Option<[f32; 256]>`（None =
  关闭；数组 Copy 直存 LUT，构建一次贯穿 decode 链）；shoot_ratios 组合处
  `lut[shoot_v_of(...)]` 查表；
- 旧键 `image_full_sharpen_white_edge_soft` 删除（不留 alias）。

**测试**：新增 `白边曲线LUT构建`（折点落值/段中点插值/隐含首点/末点平坦/
非法回退三例/空关闭）；`sharpen_full_白边抑制` 断言不变（强边亮侧 < 暗侧、
curve=[] 对称、细纹理不误伤——默认曲线下强边 shoot_v≈225 落 0.42 档仍
成立）。189 项全过。架构 13.4 / 07 键表同步。

## 7. 教训

- **预算封顶的取整方向**：像素预算类 clamp 用 round 会因四舍五入反超预算
  1~2 像素积，整数域约束一律 floor（或缩后校验再缩）；
- **badge 与原图倍率是两把尺子**：badge = zoom×ppp（基础纹理相对倍率），
  用户感知的「304%」在 150% DPI 下是原图 456%——面向用户的倍率描述须先换算；
- 旧 mipmap 论证随密度语义失效：×2 时代 full 工作区纯放大（LOD 恒 ≤0 不碰
  mip 链），×3 时代触发区间恒缩小采样——TEX_OPTS_FULL 无 mipmap 的正确理由
  从「放大用不到」变为「三线性会混入 mip1 打回增益」，结论不变论据反转，
  文档必须跟着重写而不是沿用。
