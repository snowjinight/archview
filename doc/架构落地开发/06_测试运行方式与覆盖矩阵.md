## 6. 测试运行方式与覆盖矩阵

> 从 README 迁入（用户向文档只保留用法与配置）。会话化专项断言明细见[本文 §5](05_解压会话化回归测试.md)。

### 6.1 运行方式（两段式冒烟流程）

```bat
run_tests.bat
```

三段式（逐段 errorlevel 检查，任一段失败即中止并报 SMOKE FAIL）：

1. **夹具生成** `cargo run --bin smoke_setup`——清空重建 `smoke/` →
   依赖检查 → 按测试族生成夹具；
2. **测试** `cargo test -- --nocapture`——夹具/依赖缺失即 panic 带指引，
   **禁止静默跳过**（此前的"eprintln + return"软跳过已全部清除）；
3. **VarTidy CLI 冒烟**——dry-run → 实际整理 → 幂等重跑（原 `test_tidy\setup.bat`
   流程吸收为第 3 段，夹具来自 `smoke/vartidy/`）。

夹具只在第 1 段生成、测试只消费不生成（生成与测试彻底分离），
`smoke/` 整目录 gitignore，新人 clone 后 `run_tests.bat` 一把过。

### 6.1.1 依赖语义与夹具族矩阵

依赖检查语义（`src/bin/smoke_setup.rs`，附属工具 bin，不依赖主 crate 代码）：

| 依赖 | 属性 | 缺失时 setup 行为 | 缺失时测试期行为 |
|---|---|---|---|
| ffmpeg | 必需 | 汇总列出缺失项后 exit(1) 中止 | ——（夹具已保证存在） |
| libmpv-2.dll | 必需 | 同上（探测 `ZIP_VIDEO_MPV_DIR` → `deps/mpv-dev` → `target/{debug,release}`） | 同上 |
| ffprobe | 可选 | 警告 | encode e2e 软降级跳过精确帧数断言（核心链路由 mpv 回读覆盖） |
| WinRAR rar.exe | 可选 | 警告（探测 `ARCHVIEW_TEST_RAR` → Program Files） | rar 三测试 panic「冒烟夹具缺失」 |

夹具族（`smoke/<族>/`，libmpv-2.dll 每族独立副本防并发抢占公共 DLL）：

| 族 | 内容 | 消费者 |
|---|---|---|
| player_e2e/ | libmpv-2.dll + clip.mp4（3s testsrc2 320x180）+ test.zip（两 entry Deflated） | player::tests 7 个 e2e/FFI 测试 |
| encode_e2e/ | libmpv-2.dll（dump 帧纯 Rust 构造，无文件夹具） | encode::tests e2e_encode_nv12_sequence |
| rar/ | test.rar（a.bin 50k×0x09, -ep）+ plain.rar / solid.rar（3×30k 填充 7/8/9，solid 加 -s）+ enc.rar（-p 内容加密）/ enchead.rar（-hp 加密头，密码统一 smoke-pw-123） | rar_vfs::tests 四测试（payload 与断言逐字节一致；加密双包 = 密码探测链回归 §1.10） |
| img/ | anim2.webp（红/蓝 20x14 两帧 @100ms） | imgview decode_动画webp逐帧、ui compare webp_animated |
| diag/ | 641.webp / 1000.webp（testsrc2 动画 webp） | player diag_webp_load_latency |
| vartidy/ | pack1-6 + var_repo | run_tests.bat 第 3 段 |

**随机化边界**：外观类内容每次生成随机（player_e2e/diag 视频 hue、anim2.webp
色值在断言包络内、player e2e 的 nv12 Y 平面随机字节）——测试断言只锚定
时长/尺寸/结构/通道优势区间，随机内容可锻炼不同码流；字节内容锚定的夹具
（rar 填充字节、vartidy 去重包对）保持固定，随机化会削弱甚至破坏测试语义
（如 dedup 依赖"同内容对"）。

工具路径登记在 `smoke/env.toml`（`[tools]` ffmpeg/ffprobe/rar 绝对路径 +
`[paths]` mpv_dll_src），测试侧经 `src/smoke.rs::tool()` 读取，
**代码内零硬编码路径**（原 `D:\11_software\ffprobe.exe` 兜底与
`ARCHVIEW_TEST_FFMPEG` 环境变量探测已删除）。测试侧夹具定位统一走
`crate::smoke::require / require_dll_dir`（基于 `CARGO_MANIFEST_DIR`，
缺失即 panic 指引先跑 smoke_setup）；解压/写盘类测试另开 pid 后缀独立
scratch 目录，不写只读夹具目录；此前 5 处固定名临时目录已补 pid
（meta.rs / search/history.rs / file_vfs.rs / rar_vfs.rs pw_probe），
消除并行碰撞。

### 6.2 覆盖矩阵

| 测试 | 验证内容 |
|---|---|
| VFS 单元测试 | ZIP / 7Z / RAR 各自的列表、读取、seek 正确性；7Z 测试包由 sevenz-rust 纯代码构造，无外部依赖；RAR 包由 smoke_setup 预生成（见 §6.1.1） |
| DirVFS 单元测试 | 目录媒体集合：递归收集与字典序确定性（跳过压缩包/非媒体）、条目读取与 seek 正确性、未知条目报错与空目录空集合、根不可读报错 |
| 目录模式集成（UI 层） | spawn_open 目录分支真实线程链路（DirVFS::open → stream_cb 注册 → Done 消息）、打开终态状态迁移（FastSeek→stream 标志/视图重建）与空目录统一提示 |
| e2e 流式播放 | headless mpv（vo=null ao=null cache=no）经 zvf:// 协议真实播放 deflate ZIP 内的 mp4（夹具 smoke/player_e2e/test.zip），验证下游 / 上游 seek，以及 EOF 后切换视频能正常续播（keep-open 暂停粘滞回归，见 [§3.0](03_播放流畅性专项.md) 备忘） |
| e2e 解压播放 | 构造 7Z 包（内嵌 smoke/player_e2e/clip.mp4 夹具）→ 后台解压 → headless mpv 播放本地文件全链路 |
| flag 属性循环 | pause / mute 属性经 flag 格式读 → 翻转 → 写 → 读，覆盖空格暂停、静音按钮的行为路径（FLAG 格式约定见 [§3.0](03_播放流畅性专项.md) 备忘） |
| VarTidy | 分类规则（五类非法+合法路径）、仓库只读三道闸（含 rename 不覆盖）、两级去重（CRC 判重）、密码候选链路（AES zip / 7z 加密头与内容加密 / 同批次多包各不同密码乱序命中 / 中文与特殊字符密码）、中文/空格/特殊字符作者名与包名全链路 |
| 滑动窗口冒烟（UI 层） | 模拟用户批内来回跳动 0→1→0→2→（解净空闲）→5→0：断言解码线程全程不重启（cancel 句柄同一性）、预取窗口随观看位置滑动、缓存命中立即播放、全部落地文件逐字节内容校验（明细见 [§5.2](05_解压会话化回归测试.md)） |
| config | TOML 默认模板与代码默认值防漂移、序列化往返、特殊字符密码（`#`/空格/中文）引号保留 |
| RAW 媒体 | config：pixfmt 名单数量快照与容器位数口径、raw 可见性预设唯一入口（`is_video_ext = video_extensions 命中 ∨ raw_demux(name)`，`raw.extensions` 清单已移除）与 glob 匹配、默认模板含 [raw] 节；imgview：RAW 扩展名判定（裸名不误伤）、垃圾字节 fall through、EXIF 八方向映射；ui：raw_demux_opts 四类拦截（pixfmt 名单 / 宽高为 0 / 文件大小不整除帧字节 / bit_shift 越界或非 le）+ 无预设非标名不拦截交 mpv 的文案与拼参格式；player e2e：纯 Rust 造 nv12 → rawvideo 选项装载 → 起播/时长=帧数÷fps/尺寸/帧精确 seek + 装载失败事件与日志链路（坑见 [§8.3](08_RAW媒体支持专项.md)） |

### 6.3 headless e2e 原理

e2e 测试不需要人工看画面：mpv 以无渲染模式运行，通过 `time-pos` / `pause` /
`eof-reached` 等属性断言播放状态，`cache=no` 强制 seek 请求打到 VFS 层，能真实
暴露流实现缺陷。

外部依赖（ffmpeg / libmpv-2.dll / WinRAR）与缺失语义见 §6.1.1——
**必需依赖在 setup 阶段前置把关（缺失 exit(1) 汇总列出），测试阶段夹具
缺失即 panic 指引重跑 smoke_setup，无任何静默跳过路径**。
